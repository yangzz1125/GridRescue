# GridRescue：队员提交与答辩核对稿

本稿供队员理解作品、排练和完成提交，不是参赛资格证明、获奖承诺或官方格式替代品。

## 一句话讲清作品

我们做的是极端天气下配电网恢复的离线预案原型：给出恢复候选，并检查医院生命线任务、配电网物理可行性和碳清单证据。供电服务变差时，即使碳排数字降低，也不能称为同服务减排。

## 两位讲解者分工

- 讲解者A：问题、应用、真实数据与假设边界，解释为什么不能只追求更低碳数字。
- 讲解者B：打开软件，演示电网恢复、三门、失败反例、服务与碳排对照，回答指标与验证问题。

分工不是参赛人数安排。团队人数以赛事正式规则和学校审核为准；AI不计入队员。当前获知通知要求3至6名符合条件学生，应立即由学校确认你们登记人数和资格，不得虚列成员。

## 三分钟讲稿

### 0:00–0:35 问题

“灾后恢复不是把所有负荷尽快点亮这么简单。医院的特定任务可能要求连续供电和更高电压标准；线路可能过载；少供电又会让碳清单看起来更低。我们希望让这些代价和拒绝理由在方案评审时显式可见。”

### 0:35–1:20 系统

打开默认暴雨页面，展示33节点网络和逐小时变化，点选一个节点。说明三种策略生成不同恢复结果，物理层复核分岛、电压和热限，Care检查任务，MRV核对输入、活动和清单。

“这是一套公开算例研究原型，不连接现场开关。页面显示的是仿真结果，不是现场实时监控。”

### 1:20–2:00 结果

“固定36个合成压力场景形成108条策略记录。碳韧策略有一次反馈未通过，正式配对使用35组。相对最小失供参考，平均碳清单低2409.39 kgCO2，但总失供电量高3290.27 kWh，所以不能把它包装成无代价减排。零失败预算下，系统风险推荐的是最小失供策略。”

只比较同一图的相同单位。不要将kgCO2、kWh、kW混用。

### 2:00–2:35 拒绝与验证

选择明确标注的NO_GFM演示预设，说明它是演示资格拒绝，不是重新发生了一场真实事故。再展示武汉高温公开天气案例，两个优化策略虽通过一般物理和MRV，但生命线任务不满足，真实计算资格被阻断。

“我们还用独立PYPOWER求解器复核六类案例的550个可求解分量时段，电压、线损和支路功率一致。392个停电或单节点分量列为不适用，没有算成通过。”

### 2:35–3:00 边界与应用

“第一步应用是医院、园区或馈线的离线预案比较。下一阶段必须接入经授权的真实参数和历史工单，再做盲测及安全分析。我们现在证明的是软件计算与证据链可复核，不是已实现真实减排或部署。”

## 必须理解的八个词

| 词 | 解释 |
|---|---|
| kW | 某时刻功率，即供电快慢 |
| kWh | 一段时间累计电量；1 kW维持1小时等于1 kWh |
| EENS | 本项目场景窗口内累计未满足电量，越低表示供电损失越小；合成场景集不等于真实概率预测 |
| CareTask | 合成生命线任务合同，检查功率、时窗、连续性、电压和依赖，不是临床标准 |
| 潮流 | 用电网参数和节点注入计算电压、支路功率与损耗 |
| MRV | 本项目的活动与碳清单证据复核，不是第三方认证 |
| CVaR95 | 当前样本中最差尾部服务损失的统计量，不是保证灾害只有5%风险 |
| 持续恢复 | 从某时刻到窗口结束一直全供电；首次全供电之后可能再次失供 |

## 被追问时怎么答

**你们提出了新的潮流算法吗？** 没有。采用成熟的径向潮流方法，新增的是它与服务合同、调度反馈、主张门和证据导出的集成，独立牛顿法用于交叉检查。

**CareTask让成功率提高多少？** 当前去合同消融未证明任务成功率提高。暴雨与高温去合同后仍完成原任务，台风失败点保留。我们不把未观察到的增益写成成果。

**为什么叫最小失供，能证明全局最优吗？** 这是策略名称；调度子问题使用凸优化，修复顺序与联络选择是启发式，整体没有全局最优证明。

**天气真实，是否就是武汉真实停电复原？** 不是。天气来自公开ERA5再分析；网络是公开33节点算例，故障、修复和资源为假设。雨风没有经过真实工单校准成故障模型。

**为什么年度因子用于历史天气？** 是跨年度参考情景，不是历史排放重建。0.5306 kgCO2/kWh是2023全国平均，不是地区逐小时边际因子。

**测试都通过，是否说明能上线？** 不说明。回归测试与独立静态潮流只覆盖模型内行为，还缺真实数据、保护配合、动态分析、权限审计和现场安全验收。

**AI做了什么？** 按实际情况说明AI参与代码实现、检查和文稿辅助，哪些工作由真人设计、运行与复核。不要把AI生成过程说成团队独立手写；具体披露位置与要求由学校和赛事秘书处确认。

**不懂某个技术细节怎么办？** 指出对应参数、报告或源码位置，承认需要核对，不编造医院标准、用户数量、合作单位或实验。

## 上传前由真人确认

- 核对正式比赛名称、队员人数及资格、学校推荐审核和系统中的实际截止时间。本地文件生成不能代替报名成功。
- 下载官方最新申报模板并填写，核对签字盖章、匿名版本、文件格式、大小限制及命名。项目PDF只是正文内容稿。
- 检查匿名材料中的学校、学院、导师、姓名、文件属性、截图和链接。自动路径扫描不等于匿名审核通过。
- 询问AI辅助使用及披露规则、第三方素材和数据授权要求；保留实际贡献记录。
- 使用新Audit提交包，不提交旧ZIP。保留SHA256，上传后核对系统回执和最终文件。
- 至少在另一台机器解压、安装和演示一次；提前打开三个核心场景。若网络不可用，用本地公开数据快照，不在线重抓。
- 两位讲解者都必须能解释上面八个词、三组关键数字和四项边界，不只背讲稿。
