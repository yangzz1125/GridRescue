# 单人主导执行与最小组队方案

## 结论先行

GridRescue 的工程、申报材料和演示链已经由项目负责人完成。当前真正需要补齐的是报名主体：2026 年公开赛事通知要求参赛队伍为 **3–6 人**，允许跨院校、跨年级、跨专业组队；队长登录报名，全部队员需要完成入队确认/资格审核。

因此采用“**1 名技术负责人 + 2 名低负担真实队员**”方案，不推倒重做项目：

| 角色 | 真实工作 | 最低交付 |
|---|---|---|
| 项目负责人（你） | 电气建模、算法、代码、最终答辩 | 维护仓库、主讲技术、提交材料 |
| 队员 A：实验复核 | 按 README 跑一次命令，核对 3 个指标和 1 个失败反例 | 一页复核记录 + 线上报名确认 |
| 队员 B：材料/演示 | 按脚本录一遍 5 分钟演示，指出听不懂的 3 处 | 一次彩排记录 + 线上报名确认 |

两名队员不需要改核心算法，也不需要长期维护代码；但必须是真实参赛者，完成报名、资格确认和实际分工。

## 对外招募文案（可直接发送）

> 【招募双碳赛队友｜低负担】我是华中科技大学电气方向研究生，已经完成一个纯软件作品：极端天气下配电网故障恢复与低碳保供数字孪生平台。核心代码、界面和申报书已有，现补 2 名队员组队参赛。你只需参与一次实验复核或视频彩排，确认报名信息并在答辩前熟悉自己的 1 分钟内容，不要求写代码。可跨专业/跨院校组队，感兴趣直接私聊。

## 10 天单人主导节奏

```text
D1：补齐两名真实队员，确认指导教师和队名
D2：队员 A 跑 README 快速开始，记录复核问题
D3：队员 B 按脚本完成第一次录屏
D4：主负责人修复阻断问题，不扩张算法范围
D5：盲审申报书、主张边界和图片
D6：冻结视频、申报书和 ZIP
D7：全流程彩排，准备台风 BLOCKED 反例问答
D8：校内报名/资格确认复核
D9：双备份、hash、匿名性和上传文件检查
D10：正式提交并保存回执
```

## 与 AI 协作的边界

- AI 负责代码、测试、文档、图表、答辩稿和复现命令；
- 队员负责真实的复核、讨论、彩排和报名确认；
- 申报材料只填写真实队员、真实指导教师和真实贡献，不把 AI 写成报名队员或署名作者；
- 任何数字变化先更新 `docs/competition_factsheet.yaml`，再同步 README、申报书和视频脚本。
