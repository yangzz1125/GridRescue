# Wave 5：GridRescue 数据可信度审计与申报口径

**审计日期：2026-08-22（北京时间）**  
**审计范围：** `data/`、`src/gridrescue/`、`artifacts/`、已有 `research_wave/` 文档及前端展示所依赖的导出结果。  
**审计性质：** 静态证据与可追溯性审计；本轮未改动业务代码、参数或既有结果。

## 0. 结论先行

当前项目的可信底座是**公开标准算例**，不是现场配电网实测系统：`data/case33bw.m` 与其 33 节点、37 支路、P/Q、R/X、基值参数可定位至 Baran–Wu/MATPOWER；其余灾害、资源、热限额、时序和排放因子大部分为工程设定或确定性合成。仓库当前没有原始电表、SCADA、气象下载缓存、抢修工单、柴油票据、车辆油单或真实资产台账，因此 **A 类“真实测量”当前为 0 项**。

因此申报材料须把证据分层：

- **可直接宣称**：公开标准算例上的、可复跑的算法/方案比较；结果文件可用哈希冻结。
- **可条件宣称**：采用明确版本、地域、年份、许可证和原始文件哈希的公开因子/历史气象数据后的回放或敏感性结果。
- **只能作为情景推演宣称**：当前三灾种、24 小时时序、蒙特卡洛、多资源配置、支路额定值、关键负荷分级及碳排结果。
- **不可写成“真实现场效果/实测减排/实时碳因子/真实武汉馈线验证”**：在引入相应原始数据、证据链和复算结果前均不成立。

## 1. 数据分级规范：A/B/C/D/E

本项目只使用以下五类**输入证据等级**；每个字段必须有唯一主分类。一个数据可有多个参考来源，但其徽章以最弱、最贴近当前实际使用方式的分类为准。

| 类别 | 名称 | 准入条件 | 当前项目示例 | 可用于何种结论 |
|---|---|---|---|---|
| **A** | 真实测量 / 运行记录 | 原始仪表、SCADA、气象站、工单、油单、GPS 等；可提供采集主体、设备/方法、时间、地点、原始文件哈希及脱敏规则。 | **当前无。** | 在其时空与质量范围内的实际运行描述、校准/验证。 |
| **B** | 公开权威 / 标准数据 | 官方部门、国际组织、标准基准库或公开机构的数据原件；版本、发布日期、许可/条款与文件哈希明确。 | MATPOWER `case33bw`；未来冻结的生态环境部电力因子、ERA5/CLDAS 原始快照。 | 标准算例验证、公开历史回放、可复核因子计算。 |
| **C** | 文献参数 | 同行评审文献/标准方法中的参数、曲线或模型；须给 DOI/版本、页码/表号、适用范围和二次引用说明。 | 当前代码中**没有已落实到字段级、带页码的 C 类参数**；Baran–Wu 论文是 B-NET-001 的文献锚点，而非把本地情景参数自动升级为 C。 | 有边界的敏感性、先验范围、方法依据；不可冒充现场标定。 |
| **D** | 工程假设 | 团队基于需求、约束、专家判断或演示目标设定的输入；应给所有者、版本、理由、范围、不确定度和审批状态。 | 热限额、PV/BESS/柴油容量和位置、优先级、调度权重、情景参数。 | 透明的方案推演、敏感性分析；不可作为真实资产事实。 |
| **E** | 合成场景 / 模拟生成 | 由规则、随机数、优化器或仿真生成；必须绑定生成器版本、种子、上游数据卡和输出哈希。 | 24h 负荷/PV/碳时序、三灾种、30 组 Monte Carlo、策略/潮流/排放结果。 | 方法可复现性、算法对比、压力测试；不可单独证明现实外推。 |

**派生结果规则：** 结果 CSV/报告不是第六类“原始数据”。它们标记为 `DERIVED`，并继承上游中最弱的主分类；例如当前 `artifacts/typhoon_v03/strategy_comparison.csv` 的主徽章为 **E 合成推演**，即使网络拓扑来自 B 类。

### 3.2 必填字段与校验规则

| 字段组 | 必填字段 | 硬校验 |
|---|---|---|
| 身份 | `data_id,name,class,status,purpose` | class 只能为 A/B/C/D/E；`status` 不得缺失。 |
| 来源 | 发布者、标题、URL/DOI、版本、发布日期、获取时间 | B/C 未填版本或来源定位时状态只能为 `pending`。 |
| 时空与单位 | 地域、时间区间、时区、分辨率、字段、单位、坐标/映射方法 | 不得将“基准系统”留空而暗示真实地区；单位转换必须写公式或脚本。 |
| 许可 | 名称、条款 URL、署名文本、再分发状态 | `pending` 许可证的数据不得外发原始副本。 |
| 完整性 | 路径、字节数、SHA-256、规范化方法 | 派生 CSV 还须列 `parent_data_ids` 与 `generator_sha256`。 |
| 质量 | 缺失率、校验、精度/不确定度、局限 | D/E 必须写“假设/合成”理由，不能仅填 `N/A`。 |
| 治理 | owner、审批、复核日期、弃用版本 | 结果上线前必须有 `approved` 或 UI 显示 `conditional`。 |

### 3.3 排放因子专用卡 / Factor Registry

每一个因子采用不可变 ID，例如 `EF-CN-GRID-2023-LOCATION-V1`；结果文件写 ID，绝不把数值散落在代码和报告中。

| 字段 | 含义 |
|---|---|
| `factor_id, factor_version` | 唯一标识和修订号；数值变更必升版本。 |
| `value, unit, gas_basis` | 例如 `kgCO2/kWh` 或 `kgCO2/kWh`；二者不可混填。 |
| `activity` | `grid_import` / `diesel_generation` / `vehicle_fuel` 等。 |
| `geography, year, temporal_resolution` | 全国/区域/省、年份、年度/小时；年度因子不得伪装成实时边际因子。 |
| `method, source_class, source_id` | location-based、燃料法、文献估算等与其 A/B/C/D 分类。 |
| `source_url, publication_date, retrieved_at_bjt, license` | 外部证据和合规定位。 |

## 5. UI 可信度徽章与交互规范

### 5.1 双层徽章：来源类型 + 可用性

每一个 KPI、图、下载 CSV、策略卡和风险卡至少显示一个来源类型徽章；涉及结论时再显示可用性状态。颜色不承担全部含义，文本和悬浮说明必须同时存在。

| 徽章 | 文本 | 色彩建议 | 语义 | 示例 |
|---|---|---|---|---|
| **A** | `A 实测 / 已校验` | 蓝绿 | 原始测量或运行记录，且通过质量检查。 | 未来：脱敏 SCADA 15 min 电量。 |
| **B** | `B 公开权威 / 标准` | 蓝 | 官方/机构/标准算例，已冻结版本和哈希。 | `case33bw` 网络参数。 |
| **C** | `C 文献参数` | 紫 | 文献/标准条款给出的范围或模型参数。 | 未来：柴油 SFC 曲线。 |
| **D** | `D 工程假设` | 黄 | 团队设定，须可编辑、可查看理由和敏感性。 | 支路 1,600 kVA 限额。 |
| **E** | `E 合成推演` | 橙 | 合成或仿真生成，必须有 seed/生成器。 | 台风 24h 负荷/碳时序。 |
| **DERIVED** | `派生结果` | 中性灰 | 结果来自多个上游；旁列上游最低等级。 | 策略对比表：`派生 · 主等级 E`。 |

可用性状态：

- `已冻结`：版本、来源、许可、哈希、单位齐全。
- `条件可用`：可运行但有 D/E 上游或缺少外部验证。
- `待补证`：缺版本、许可、原始文件、单位或来源；不可作为“权威/实测”结论。
- `不适用`：例如标准算例没有真实地理范围。

| 页面/组件 | 必显内容 | 具体文案示例 |

### 5.3 防误读规则

1. **禁止只显示一个“可信度 95%”总分。** 来源等级、校验状态和不确定性必须分开。
2. **D/E 参数可点击追溯。** 点击后看到取值、责任人、理由、范围、敏感性和上游数据卡。
3. **年度因子显式标注“非实时边际因子”。** 合成的小时形状显式标注“由年度因子 × 情景乘子生成”。
4. **弃绿不是减排徽章。** 只显示 `新能源弃电/消纳`；仅在服务等价通过后，才显示 `Inventory 差额`，并附因子版本。
5. **红色只表示已发生或已设定的故障；橙/紫只表示风险或情景。** 不把合成风险画成事实故障。

## 6. 申报书、海报和答辩表述

### 6.1 可直接采用的表述

**项目数据边界（建议放在“研究基础/实验设计”）：**

> 本项目当前以公开的 MATPOWER `case33bw` 标准配电网算例为电气基准，使用其 33 节点、37 支路、P/Q 负荷及 R/X 参数开展可复现实验。灾害故障、资源配置、热限额、恢复时序与部分碳参数按版本化工程假设和确定性合成规则构造，所有输出均附场景、随机种子、输入版本和哈希。项目定位为预案级数字孪生与方法验证，不将标准算例结果外推为某一真实地区配网的实测成效。

**碳口径（建议放在“低碳创新/可信 MRV”）：**

> 恢复阶段排放按购电、柴油和抢修交通活动数据核算；弃光仅作为清洁能源利用指标，不直接折算减排。策略间减排结论须在相同灾害、资源、负荷和因子版本下，通过服务等价与物理可行性门控后，以运行排放清单差额报告。当前原型中的未版本化因子仅用于敏感性推演，正式因子表将冻结来源、地域、年份、单位、许可证和文件哈希。

**场景与统计（建议放在“实验结果”）：**

> 30 组实验为固定随机种子下的合成多故障压力测试，用于比较算法在共同输入上的可复现表现；它不等同于真实故障样本统计或现场稳健性验证。后续将用冻结的公开历史天气、脱敏资产台账和事件记录完成区域化校准与外部验证。

**AI 模块（建议放在“智能化创新”）：**

> 当前风险模块在无真实故障标签时属于工程先验驱动的合成演示；界面会明确显示数据模式。只有在事件级切分、冻结测试集和校准检验完成后，才报告相应范围内的历史回测指标。

## 9. 审计结语

GridRescue 现阶段的强项不是“拥有大量真实数据”，而是已经有一个可公开检查的标准网络基准和确定性推演闭环。可信度提升的关键不是把 D/E 包装成 A/B，而是让每个数字清楚回答：**它来自哪里、适用于何时何地、单位与版本是什么、许可是否明确、文件能否按哈希复得、它是事实还是假设、结论是否越过了数据边界。**
