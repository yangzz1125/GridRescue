# GridRescue 一等奖 5 分钟演示与 Streamlit 信息架构

> **目标**：将现有“故障恢复 + 三策略 + 能源碳流 + 潮流校验 + MRV 报告”原型，导演成评委五分钟内能够看懂问题、相信结论、追溯证据的软件产品展示。本文只做展示设计，不修改代码。

## 1. 主叙事与展示边界

### 一句话主叙事

> 极端天气发生后，GridRescue 不只展示“哪里断了、恢复了多少”，而是把医院生命线任务、成岛资格、韧性—碳排权衡和 MRV 证据链放进同一条决策链：**先保服务与物理可行，再谈低碳。**

### 评委的五个连续问题

| 时间 | 评委问题 | 必须给出的证据 | 答辩口径 |
|---|---|---|---|
| 0:00–0:35 | 灾害造成了什么后果？ | 故障支路、关键节点、初始失供、场景参数 | 不是静态拓扑，而是 24 小时恢复过程。 |
| 0:35–1:25 | 系统给出的动作有什么价值？ | 同一输入下三策略、动作时间线、恢复差异 | 资源相同，只改变恢复决策。 |
| 1:25–2:15 | 关键负荷为什么不是一个百分比？ | 医院任务、依赖、截止时间、阻塞原因 | 保供被解释为可审查的设施任务。 |
| 2:15–3:15 | 孤岛真的能持续运行吗？低碳是否牺牲服务？ | 成岛护照 G0–G7、Pareto、服务门 | 先过物理与任务门，再展示碳差异。 |
| 3:15–5:00 | 结果可信吗，是否可复算、可推广？ | Carbon-SOC、因子质量、MRV、30 场景扰动 | 每个数能回到逐时能量流、因子和输入输出证据。 |

### 边界与演示纪律

1. 全程锁定一个主场景：**暴雨内涝 / 碳韧协同恢复 / 固定 seed**。现有场景含 L6、L13、L27 三处故障，PV 降额 0.38、抢修距离 46 km。
2. 医院任务、成岛护照、Carbon-SOC、MRV seal 均在界面角标标注“合成原型 / MVP”，不伪装成真实馈线或真实医院控制。
3. 不现场重算蒙特卡洛，不编辑参数，不打开长 CSV；现场只做页面切换、小时滑杆、点选和下载。
4. 演示使用会前固定的 demo run。当前 flood_v03 示例中：传统顺序恢复关键负荷恢复率为 87.2%，最小失供和碳韧协同均为 100%；碳韧协同的 24 h 运行排放清单为 41,178.6 kgCO2、EENS 为 4,787.7 kWh。示例数仅用于固定快照，不作为普适承诺。
5. 一条主线：故障 → 医院任务 → 成岛护照 → Pareto → Carbon-SOC → MRV 证据链；不按功能菜单逐页讲。

## 3. Streamlit 信息架构：最小增量

### 顶层结构

- 全局侧栏：灾害场景、恢复策略、恢复小时、演示模式。
- 标题下新增全局状态条：run 短码、seed、服务门、物理门、MRV 状态。
- 主区保持六个 tab：
  1. 恢复数字孪生（现有，增强医院入口）
  2. 三策略对照（现有，嵌入 Pareto 和服务等价门）
  3. 能源与碳流（现有，嵌入 Carbon-SOC）
  4. 潮流校验（现有，增加最弱约束跳转）
  5. 成岛护照（唯一新增顶层 tab）
  6. MRV 报告（现有，升级为证据中心）

### 页面职责与用户路径

| 页面 | 首屏只回答什么 | 最小组件 | 演示点击顺序 | 不要放什么 |
|---|---|---|---|---|
| 恢复数字孪生 | 哪里断、修到哪、谁有风险？ | 拓扑、小时滑杆、动作表、医院入口 | T+0 → T+7 → N18 | 长算法说明、全量 hash |
| 三策略对照 | 为什么不选传统或单目标？ | KPI 差值、柱图、Pareto、服务门 | 传统反例 → Pareto → 推荐理由 | 24 行逐时表 |
| 能源与碳流 | 能源来自哪里，电池碳是否算对？ | 能源图、SOC 图、碳分项、Carbon-SOC 抽屉 | 点高负荷小时 | 把弃光潜力加进主排放总计 |
| 潮流校验 | 方案是否物理可行？ | V/负载率、可行 badge、最弱约束表 | 当前小时 → 最弱节点/支路 | 只报均值 |
| 成岛护照 | 这个非根岛能否承诺供电？ | 热图、G0–G7、岛卡、证据抽屉 | 点黄/灰格 → 约束细节 | 只凭 DER 容量宣称 GFM |
| MRV 报告 | 结果从哪里来，是否可复算？ | badge、因子卡、证据链、下载组 | seal → 链 → 下载 | 首屏塞满 JSON/CSV |

### 全局联动规则

- scenario + strategy + hour + run_id + seed 是所有页面共享状态。
- 小时滑杆同步拓扑、动作表、医院任务、护照、能源曲线 marker 和潮流明细。
- 现场只允许在对照页显式切策略；其余页面的演示模式锁定推荐策略。
- 所有详情采用右侧抽屉或 expander，不因点击离开当前叙事页面。
- “查看潮流证据 / 查看护照 / 查看 MRV 证据”按钮必须携带 hour、node、island episode、action ID。

## 6. 失败态、空态与加载态

### 统一颜色

| 状态 | 颜色 | 文案规则 | 页面行为 |
|---|---|---|---|
| PASS / READY / verified | 绿 | 已通过当前门控 | 允许显示推荐或比较结论 |
| WARNING / CONDITIONAL | 黄 | 有裕度或数据质量限制 | 显示限制与最弱约束 |
| BLOCKED / FAIL / invalid | 红 | 结果保留，结论锁定 | 显示具体原因和回退方向 |
| UNKNOWN / missing | 灰 | 数据不足，不下结论 | 显示缺少的字段或证据 |
| LOADING | 蓝 | 正在加载快照或推演 | skeleton，不显示零值假结果 |

### 必备空态与失败态

| 场景 | 触发条件 | 必须显示 | 下一步 |
|---|---|---|---|
| 无演示 run | 首次打开或快照缺失 | “尚无推演快照”，网络/场景摘要，不显示零 KPI | 加载演示 run |
| 当前小时无动作 | 无修复/开关发生 | “T+Nh 无新增动作，执行上一阶段计划” | 跳下一个关键小时 |
| 医院任务未接入 | 当前仅有聚合关键负荷 | “医院任务链为下一步 MVP”，显示 N03/N18 映射 | 查看 schema/原型说明 |
| 医院任务阻塞 | 失电、功率不足、依赖未成、电压异常、错过时限 | block_reason、发生小时、影响任务 | 查看护照或潮流 |
