# GridRescue 一等奖导向创新增强波（12项、10天可落地）

> **定位**：从双碳大赛一等奖评委视角，不再给现有原型叠加“算法名词”，而是把它升级成一个能在灾前预判、灾中保命、灾后可核查、面向政策和试点可解释的**碳韧性恢复决策系统**。
>
> **评审判断**：GridRescue 目前已有 IEEE 33 节点、三类极端天气、三策略对照、径向/潮流后验校验、孤岛识别、DER 调度、恢复动画和基础 MRV 报告。冲一等奖的关键不是再加一张碳排图，而是证明：**碳信息会改变恢复动作；关键任务不会为减排被牺牲；每一个结论可由天气、拓扑、能量流和因子追溯；结果可映射为应急与新型配电网政策语言。**

## 1. 评分口径与结论先行

- **创新性**：相对“配网恢复 + 多目标优化 + 可视化”的常见参赛作品，是否形成可辨识的新对象、新约束或新证据链。
- **技术可信度**：10天内能否以现有 `case33bw`、小时级天气、现有潮流校验和合成 DER 参数做出可复算验证；分数高不等于可直接声称工程级试点。
- **演示冲击**：五分钟答辩中是否能由一个参数/故障/天气变化引发清晰、肉眼可见且可解释的决策变化。
- **开发成本**：`1=最低，10=最高`，包括建模、数据、UI、测试和文档成本；越低越适合10天冲刺。
- **一等奖优先级**：`0.30×创新性 + 0.30×可信度 + 0.25×演示冲击 + 0.15×(11-成本)`，满分10。它服务于冲奖排序，而不是学术价值的绝对排名。

### 必须做的“冠军六件套”

1. **#2 同服务 ε-constraint Pareto**：回答“低碳是否以少保供换来”的核心质疑。
2. **#6 动作级 MRV 因果账本**：让减排从展示数字变成可审计证据。
3. **#1 Carbon-SOC 闭环**：让储能从普通电池变成项目独有的低碳恢复资产。
4. **#4 成岛能力护照**：让“微网成岛”具备工程准入门槛，避免动画式孤岛。
5. **#5 医院临床任务链**：把“关键负荷”升级为“生命线服务”，形成最强人本价值。
6. **#3 天气—故障—可达性联动**：让天气真正改变故障、修复和调度，而非背景图。

> **主答辩一句话**：GridRescue 在极端天气下不是求一个“最低碳”解，而是在医院生命线、物理安全和灾情不确定性均被锁定后，给出可核验碳排、可执行成岛和可履约保供的 Pareto 恢复方案。

## 2. 十二个创新方向

### 01. Carbon-SOC 闭环：带来源证明的储能碳约束调度

**创新命题**：将电池 SOC 扩展为“能量余额 + 随能量携带的碳质量 + 环境属性状态”。同样是 100 kWh，雨前由现场未售出 PV 充入和由高碳电网充入，在灾时放给医院的碳解释完全不同。

- **现有基础**：仓库已有 BESS、PV、柴油、购电和 Carbon-SOC 方案文档；当前风险在于文档领先实现。
- **10天 MVP**：新增逐小时 `carbon_soc_hourly.csv`，按 `grid_location / grid_residual / on_site_pv_unclaimed / diesel / initial_unknown` 五类来源记账；在调度目标中加入两条软硬约束：
  1. 医院任务窗口内保留最小“低碳可用电量”；
  2. 已售或状态未知的绿电属性不能进入零运行排放池。
- **最有力演示**：把 PV 充电来源从“未声明自用”切换为“绿证已售”，同一个放电动作的 Carbon-SOC 标签改变；系统自动由“低碳保供”切换为“保供优先但碳债增加”。
- **验证**：能量守恒、SOC 上下界、碳质量非负、来源份额和为1、禁止双记；对同一充放电轨迹做手算抽检。
- **评委会买单的点**：不把“电池放电=零碳”当常识，正面解决环境属性重复计算和灾时储能碳漂白。
- **边界表述**：这是恢复运行阶段的方案级碳归因，不宣称替代组织层面的温室气体核查。

### 02. 同服务 ε-constraint Pareto：把“低碳”从权重游戏变成公平选择

**创新命题**：不采用容易掩盖服务差异的加权和；先锁定医院及关键任务的服务门槛，再扫描碳排或普通负荷 EENS 约束，形成真正可解释的 ε-constraint Pareto 前沿。

- **现有基础**：已有传统、最小失供、碳韧协同三策略，但当前三点并不等于 Pareto 前沿。
- **10天 MVP**：在每个场景上设置：
  - 硬约束：医院一级任务服务率 100%、关键负荷恢复时限 `T_critical`；
  - 扫描变量：`EENS_normal <= ε` 或 `CO2e <= ε`；
  - 输出：7–11 个非支配点、可行性状态、求解时间、动作差异。
- **最有力演示**：评委拖动“普通负荷可延后 0/2/5%”或“碳预算”，前沿点高亮，系统解释“为何此时先闭合 tie-3、保留电池、不启柴油”。
- **验证**：全部点统一故障、资源、天气、碳因子和关键任务门槛；剔除不通过 P/Q/V、热限、径向性及成岛条件的候选点；做非支配性检查。
- **评委会买单的点**：将低碳结论从“自选权重得到的漂亮结果”提升为可由指挥者选择的透明权衡边界。
- **政策连接**：直接呼应新型电力系统“清洁低碳、安全充裕、经济高效、供需协同、灵活智能”的综合目标，而非单一减排指标。

### 03. 天气—故障—道路—抢修可达性联动风险孪生

**创新命题**：让雨、风、热三类天气同时影响线路失效、PV降额、负荷升高、道路通行和抢修时长；系统优化的不是静态故障表，而是随天气推进的“恢复机会窗口”。

- **现有基础**：已有暴雨、台风、高温情景，且天气方案已给出 ERA5/Open-Meteo 到灾害 hazard 的映射框架。
- **10天 MVP**：
  - 从已固化小时天气 CSV 读取 `rain_6h`、`rain_24h`、风速/阵风和高温压力；
  - 每支路得到风险分 `p_fault`、每抢修任务得到道路速度折减 `travel_multiplier`；
  - 每小时刷新 PV 可用率、负荷倍率、故障/修复状态；用区域共同冲击生成相关故障。
- **最有力演示**：同一网络、同一故障数，比较“干燥道路”和“暴雨积水”两种天气：后者使靠近医院的一条抢修线路延迟，系统提前向医院岛转移 BESS。
- **验证**：固定 seed 重现；风险等级上升时故障数、修复时长和尾部 EENS 单调变化；将真实天气回放与合成压力测试明确分组。
- **评委会买单的点**：天气不再是视频背景，而是进入故障、资源和恢复时序的共同驱动。
- **数据边界**：ERA5/CLDAS 是天气事实来源；设备脆弱性参数在原型阶段为可校准先验，绝不冒充由真实停电工单训练出的故障率。

### 04. 微网成岛“能力护照”与黑启动可行性证书

**创新命题**：每一个孤岛必须获得一张实时的“能力护照”，而不是只在拓扑图中被涂成绿色。护照说明该岛何时、凭什么、以何种裕度、能维持哪些关键任务。

- **护照字段**：岛 ID、节点集合、GFM 来源、黑启动时长、SOC/燃料、可供 P/Q/kVA、最大冷负荷阶跃、电压最小值、最重载支路、可维持时长、下一个失效点、是否允许合闸/并网。
- **10天 MVP**：复用连通分量、径向性与潮流校验；新增 `island_capability.json`。设定硬失败：无 GFM、SOC/油料不足、P/Q 缺额、启动迟于医院任务 deadline、低压/过载、遥控拒动、合环或同期未知。
- **最有力演示**：故障后图上出现两个孤岛。A 岛有 PV 却无 GFM，被标红“不可自愈”；B 岛有 BESS-GFM，被标绿且显示“支撑 ICU 4.2h”。将电池 SOC 拉低后，B 岛自动从可成岛变为不可行。
- **验证**：至少覆盖无GFM、BESS SOC不足、柴油黑启动成功、PV无成网能力、无功不足、冷负荷过冲、合环和遥控拒动八类测试。
- **评委会买单的点**：形成源网荷储协同的工程语义，与智能微电网“自平衡、自调峰、提高可靠性和新能源自发自用”的政策方向一致。

### 05. 医院“临床任务链”保供：从负荷等级走向生命线服务

**创新命题**：医院不是一个加权负荷节点。ICU、手术、急诊、血液透析、冷链药品、影像和普通办公具有不同的最小功率、启动顺序、最长失供、持续时间及供电质量需求。平台优化的是**可完成的临床任务**。

- **10天 MVP 数据模型**：`CareTask(task_id, bus, min_kw, deadline_min, min_duration_h, voltage_band, cold_pickup_kw, dependency)`；默认构造三层：
  - 一级：ICU/急诊/手术持续供电，严电压阈值；
  - 二级：检验、药品冷链、通信；
  - 三级：门诊/办公及可延期服务。
- **优化连接**：把 `served_kwh` 扩展为 `task_completed`；在 ε-constraint 中把一级完成率和最长中断作为硬约束，非临床舒适负荷可成为可控弹性。
- **最有力演示**：同样恢复 1 MW，方案 A 只点亮“医院节点”，方案 B 连续保障 ICU、手术、冷链三项任务，面板给出“生命线任务 3/3 完成”；这是答辩中最直观的人本差异。
- **验证**：任务依赖、deadline、最小持续时长、冷负荷阶跃、失压和故障重启均要写入断言；不可只显示累计供电量。
- **评委会买单的点**：把电网韧性指标翻译为公共服务连续性，显著提高项目社会价值和应急场景可信度。

### 06. 动作级 MRV 因果账本：每 kgCO2 回溯到开关、资源与反事实

**创新命题**：MRV 不止是总排放报表。把每一个恢复动作（隔离、合闸、启动柴油、BESS 迁移/放电、抢修车出发）与随后的能量流、活动数据、因子版本、服务变化绑定，形成“为什么排了/少排了”的因果链。

- **10天 MVP 输出**：
  - `action_ledger.csv`：`action_id, hour, operator, precondition, topology_delta, energy_delta, emissions_delta, evidence_refs`；
  - `factor_registry.csv`：因子来源、年份、地域、单位、版本、适用边界；
  - `causal_attribution.csv`：用消融或固定顺序反事实，分解拓扑重构、PV消纳、BESS、柴油替代、抢修路径五类贡献；
  - `run_manifest.json`：输入哈希、随机种子、求解版本、输出哈希。
- **最有力演示**：点击“关闭联络线 T5”，右侧立即显示“新增医院供电 +X kWh；少启柴油 Y kWh；本动作在服务等价门槛下带来 ΔZ kgCO2”，并跳转到对应原始输入和因子。
- **验证**：归因贡献和与总差额误差受控；服务不等价时锁死“减排”标签，只显示 inventory 和 ENS；同一绿电属性不可重复进入多个声明。
- **评委会买单的点**：将“双碳”从结果 KPI 升级为可追溯、可复算、可审计的数据产品。这与碳市场法规强调的数据质量和规范化管理方向一致。

### 07. C-RSLA：碳韧性服务等级协议与履约判定

**创新命题**：将恢复算法输出转为可被供电企业、园区和医院理解的服务协议：不仅承诺容量/时长，还承诺关键任务恢复时限、最长中断、柴油依赖上限、恢复碳强度和证据完整度。

- **10天 MVP**：定义三档服务包（基础、生命线、低碳生命线）；建立 `evaluate_sla(result, scenario)`，输出通过/失败、违约原因和应急补救建议。
- **示例指标**：`ICU任务在30分钟内恢复`、`连续供电≥4h`、`柴油供电占比≤40%`、`恢复阶段碳强度≤阈值`、`MRV证据完整率=100%`。
- **最有力演示**：同一策略在“普通园区 SLA”通过、在“医院生命线 SLA”失败，系统不是给出抽象 EENS，而是指出“BESS 到达晚 20 分钟，手术任务超时”。
- **验证**：10个随机灾害场景形成 SLA 通过/失败矩阵；每项失败能定位到动作、资源或天气条件。
- **评委会买单的点**：把算法价值变成可采购、可考核、可复盘的服务成果；也使“政策价值”具有落地接口，而不是文件罗列。

### 08. 灾时“碳预算 / 碳债”控制器

**创新命题**：灾时低碳不是绝对禁用柴油，而是对“为保生命线必须额外燃烧的碳”建立显式预算、借贷和偿还机制；超预算必须被解释为医院任务或安全约束触发，而不是被算法悄悄吞掉。

- **10天 MVP**：每场景定义可调 `carbon_budget_24h` 和 `emergency_override`；在 Pareto 解中加累计排放约束，若医院一级任务触发则允许形成 `carbon_debt` 并记录原因。
- **最有力演示**：将碳预算从宽松调紧，普通负荷恢复动作改变；当 ICU 任务将失供时，系统触发红色“生命线豁免”，柴油启动，同时形成待灾后审计的碳债条目。
- **验证**：预算内方案不越限；豁免动作必须对应任务 deadline/电气可行性；碳债=实际排放-预算，且可在 MRV 中追溯。
- **评委会买单的点**：比“最小碳排”更符合灾害现场伦理与调度实际，体现保供与降碳的边界管理。

### 09. 主动信息价值（VoI）：灾中先确认哪条线、哪台 PV、哪块电池

**创新命题**：灾中通信和巡检资源稀缺。平台不只在信息完整时给方案，还主动建议“下一条最值得核验的信息”，以最快缩小医院失供和碳排不确定性。

- **10天 MVP**：选择 6–10 个候选观测（支路状态、BESS SOC、PV实际出力、道路通行）；对每项观测的可能结果重跑小情景集，计算 `VoI = 预期ENS方差下降 + 碳排区间缩窄 + 关键任务失败概率下降`。
- **最有力演示**：对三条未知线路，系统推荐先派无人机/抢修员确认 `L17`，因为它决定医院岛是否可成岛；一旦证实故障，Pareto 前沿和 BESS 去向即时翻转。
- **验证**：与“随机选一条线路核验”比较，展示关键任务失败概率、ENS方差、碳排区间宽度下降。
- **评委会买单的点**：从静态数字孪生升级为“会提问”的应急决策助手。
- **风险控制**：采用小候选集和离线情景缓存，避免十天内引入过重的贝叶斯优化或深度强化学习。

### 10. 孤岛韧性安全裕度（Resilience Margin）热图

**创新命题**：用单一而可解释的“距离失效还有多远”指标，替代非专业评委难以理解的多行潮流表；它把 SOC、P/Q 裕度、电压、热限、燃料和任务 deadline 统一为岛级安全余度。

- **10天 MVP**：定义每个岛的最小归一化裕度：
  `margin = min(SOC_margin, P_reserve, Q_reserve, voltage_margin, thermal_margin, deadline_margin)`。
  通过颜色、倒计时和“最薄弱约束”展示。
- **最有力演示**：碳韧策略与最小失供策略均让医院通电，但后者仅有 0.1 pu 电压裕度/0.3h 燃料裕度，平台明确提示“看似恢复，实则脆弱”。
- **验证**：对各单约束分别做扰动，裕度应单调下降；跨过零值即与不可行标签一致。
- **评委会买单的点**：把“物理可行”从二元勾选升级为抗二次扰动能力，极适合大屏演示和现场追问。

### 11. 可审计推演包：输入—模型—因子—动作的“证据封签”

**创新命题**：一次运行生成独立复算包，任何图表都有唯一 `run_id`。它不是区块链噱头，而是用哈希、版本、参数、日志和最小复现命令解决竞赛作品最常被质疑的“结果是否预制”。

- **10天 MVP**：自动导出 `manifest.json`、原始/清洗数据 hash、网络/天气/因子版本、随机种子、求解器参数、动作表、逐时能量表、图表 hash、复跑命令；页面为每个 KPI 显示证据编号。
- **最有力演示**：评委随机改变一条故障线路后，系统生成新 run；旧新两份 manifest 比较只显示变动输入和受影响的动作/碳差额。
- **验证**：同输入同 seed 的结果 hash 一致；修改输入后 hash 必变；在干净目录用一条命令生成同一核心 CSV。
- **评委会买单的点**：将“数字孪生”与“MRV”共同落到可审计的工程交付，而非视觉效果。
- **政策连接**：预案管理强调风险防控、监测预警、应急处置、应急保障、恢复重建的全过程安排；可审计推演包适合作为预案演练与复盘附件。

### 12. 医院非临床柔性负荷的灾时需求响应契约

**创新命题**：不是让医院整体“削负荷”，而是把办公空调、停车充电、洗衣、非紧急检验、蓄冷等非临床负荷转为带补偿/恢复承诺的可控资源，使每一度节下来的电优先服务临床任务并减少柴油依赖。

- **10天 MVP**：构造 3 类柔性负荷：可立即切除、可延后、可移时；配置最大削减、最长持续、恢复反弹和舒适/业务代价。把它们接入 ε-constraint 和医院任务链。
- **最有力演示**：灾害初期系统自动削减医院非临床 120 kW，避免启动柴油机并保障 ICU；2小时后天气风险下降，按契约平滑恢复负荷，避免二次峰值。
- **验证**：不可削减一级临床任务；需求响应持续时间、反弹功率、恢复后电压/热限均受校验；报告“由DR替代的柴油量”只作为同服务条件下的差额结果。
- **评委会买单的点**：将源网荷储互动落到医院这一高价值用户，既有社会价值，也有新型电力系统需求侧协同的明确政策接口。

## 3. 重点维度的横向比较

### 3.1 Carbon-SOC vs 普通储能优化

| 项目 | 普通SOC优化 | Carbon-SOC闭环 |
|---|---|---|
| 状态量 | 剩余电量 | 剩余电量 + 来源份额 + 已归因碳质量 + 环境属性状态 |
| 对低碳的解释 | 电池放电常被默认视作低碳 | 放电显示历史碳强度；避免“充电排一次、放电再减一次” |
| 对决策的影响 | 仅决定何时充/放 | 决定何时保留未声明PV电量、何时使用高碳库存、何时形成碳债 |
| 最大风险 | 只是传统削峰填谷 | 数据字段很多但未真正影响调度 |
| 10天验收 | SOC曲线 | Carbon-SOC账本、双算禁止测试、来源切换演示、调度动作改变 |

**判断**：Carbon-SOC 是最适合成为“本项目原创技术标签”的方向，但只有写进调度约束、导出账本和单元测试三处同时出现，才值得在答辩中作为已实现功能宣称。

### 3.2 ε-constraint Pareto vs 三策略/加权和

| 项目 | 三策略或加权和 | 同服务 ε-constraint |
|---|---|---|
| 公平性 | 权重可能暗中允许少供普通/关键负荷 | 先锁定医院与关键任务，再扫描可接受的服务或碳边界 |
| 前沿完整性 | 通常只产生几个任意点 | 得到可检查的非支配前沿 |
| 解释方式 | “权重设为0.6/0.4” | “若允许普通负荷延后2%，可少排X；一级医疗任务不变” |
| 评委风险 | 被质疑调参得结论 | 结果直接反映可选择的政策/指挥偏好 |
| 10天验收 | 三柱图 | 7–11点前沿、可行性日志、交互方案选择器 |

**判断**：#2 是最该优先落地的公平性底座。没有它，Carbon-SOC、医院任务和碳预算产生的“减排”都缺少强对照边界。

### 3.3 气象风险 vs 固定灾害脚本

| 项目 | 固定灾害脚本 | 天气联动风险孪生 |
|---|---|---|
| 天气角色 | 场景标签或背景动画 | 故障 hazard、PV降额、负荷倍率、道路可达性共同驱动 |
| 时序 | 一次性给定故障与修复时间 | 小时级风险和修复机会窗动态更新 |
| 可信边界 | 易被误解为真实预测 | 明确“真实天气输入 + 可校准脆弱性先验” |
| 演示 | 切换台风/暴雨按钮 | 雨势增强使抢修延迟、提前成岛与储能迁移的因果链 |
| 10天验收 | 若干预制场景 | 1条真实天气回放 + 1条合成压力测试 + 风险单调性/seed复现 |

**判断**：优先利用已规划的固化 ERA5/Open-Meteo 数据，避免现场联网依赖；真实天气和合成设备参数须分层披露。

### 3.4 微网成岛 vs 拓扑连通图

| 项目 | 仅识别孤岛 | 成岛能力护照 |
|---|---|---|
| 核心问题 | 哪些节点被隔开 | 哪个岛能黑启动、可带哪些任务、能支撑多久、最薄弱在哪 |
| 物理门槛 | 连通性/径向性 | GFM、P/Q/kVA、SOC/燃料、冷负荷、电压、热限、同期/遥控 |
| 对医院 | 只看到节点是否通电 | 可证明“ICU是否能在deadline前连续运行” |
| 演示 | 地图变色 | 可行/不可行证书、倒计时、失败原因、二次扰动裕度 |

**判断**：#4 应与 #5 绑定。孤岛可以存在，不代表可承诺生命线服务；护照使该区别可视、可测、可答辩。

### 3.5 医院关键任务 vs 简单关键负荷权重

| 项目 | 关键负荷权重 | 临床任务链 |
|---|---|---|
| 粒度 | “医院=高权重节点” | ICU/手术/急诊/冷链/影像等任务与依赖 |
| 目标 | 多供一点高权重电 | 按时、连续、合格电压地完成任务 |
| 结果单位 | kWh / 恢复率 | 任务完成率、最长中断、连续运行时长、失败原因 |
| 公共价值 | 技术术语 | 生命线保供的直观社会价值 |

**判断**：#5 的数据是合成任务模板也可成立，但必须在材料中写成“场景化需求模型”，而不是声称医院真实负荷/临床规范。

### 3.6 MRV溯源 vs 总量碳看板

| 项目 | 总量碳看板 | 动作级因果 MRV |
|---|---|---|
| 结果 | 一个总排放/减排数字 | 每个动作、每个能量流、每个因子与反事实贡献 |
| 核查 | 难以复算 | run manifest、输入哈希、因子注册表、逐时账本 |
| 避免误导 | 容易把少供电说成减排 | 服务等价门槛不通过即锁定减排声明 |
| 核心价值 | 展示 | 面向预案复盘、ESG/碳数据治理和未来试点接口 |

**判断**：#6 + #11 是最稳的可信度得分来源。它们不是“更酷”的页面，却是评委愿意相信全部结果的前提。

### 3.7 政策价值：从“引用政策”到“政策可执行接口”

项目可将价值落到四个政策/制度接口，而不夸张宣称已替代现有调度或碳核查体系：

1. **配电网高质量发展**：抗灾能力、供电保障、源网荷储协调、发展指标评价；对应 #3、#4、#10。国家能源局发布的《配电网高质量发展行动实施方案（2024—2027年）》明确围绕供电、抗灾与承载能力提升推进工作。
2. **新型电力系统与智能微电网**：智慧化调度、构网型技术、源网荷储互动、需求侧协同；对应 #2、#4、#8、#12。
3. **应急预案与生命线保障**：事前风险防控、监测预警、处置救援、应急保障和恢复重建的全过程；对应 #3、#5、#7、#9、#11。
4. **碳数据质量与市场化治理**：强调碳排放相关数据的真实、准确、完整、可追溯，项目在此处定位为“灾时恢复运行排放的预案级 MRV/审计工具”；对应 #1、#6、#11。

## 4. 十天落地组合：避免功能堆砌

### 推荐主线（D1–D10）

| 日期 | 只做一件关键事 | 交付与验收 |
|---|---|---|
| D1 | 冻结比较口径 | 定义医院任务模板、同服务门槛、因子注册表字段、所有策略统一输入清单 |
| D2 | #2 ε-constraint | 生成至少7个候选点；每点写入服务约束、碳、EENS、操作和可行性 |
| D3 | 物理门槛接入前沿 | 将 P/Q/V、热限、径向性、成岛可行性作为 Pareto 硬过滤；保留失败日志 |
| D4 | #4 成岛能力护照 | 输出每小时岛屿状态、GFM、P/Q裕度、可持续时长与失败原因 |
| D5 | #5 医院任务链 | 从“医院节点恢复率”替换为任务完成/超时/连续供电 KPI |
| D6 | #1 Carbon-SOC | 生成逐时来源账本，完成双记禁止和来源切换单测 |
| D7 | #6 动作级MRV | 每个方案导出 action ledger、factor registry、manifest、服务等价闸门 |
| D8 | #3 天气联动 | 接入固化天气回放，增加道路/抢修可达性与相关故障；跑多 seed |
| D9 | #7 或 #8 二选一 | 面向市场/政策讲故事选 C-RSLA；面向算法冲击选碳预算控制器 |
| D10 | #11 证据封签 + 演示 | 新环境复跑、随机改故障演示、录制“天气→任务→成岛→Pareto→MRV”完整链路 |

### 第8天后才做的加分项

- #9 主动信息价值：很新，但需要小情景集和结果缓存；主线不稳时不做。
- #10 岛屿安全裕度热图：成本低、演示好，可作为 #4 的 UI 增强。
- #12 医院柔性需求响应：适合政策叙事和可视化，但必须建立在任务链已正确锁定的基础上。

### 明确不建议在十天内投入的方向

- 全量 MISOCP/MINLP 联合恢复—潮流—车辆—医疗任务—Carbon-SOC；
- 无真实工单支撑的深度故障预测/GNN/强化学习；
- 区块链碳证书；
- 多医院真实临床系统集成；
- 声称可直接下发现场开关指令。

这些方向可写为后续试点路线，但会稀释当前最该拿下的**公平比较、物理可行、MRV可审计、生命线价值**四条主证据链。

## 5. 一等奖答辩结构（5分钟）

1. **问题（30秒）**：极端天气下恢复更多负荷不等于更低碳，少供电也不等于减排；传统系统缺少“生命线服务 + 可核验碳排”的共同决策语言。
2. **灾情进入（45秒）**：展示真实天气回放驱动风险、道路可达性、PV/负荷变化，形成多点故障。
3. **生命线决策（60秒）**：展示医院临床任务链和成岛能力护照；解释“有PV的岛为何仍不可运行”“哪项任务何时恢复”。
4. **公平权衡（60秒）**：展示同服务 ε-constraint Pareto，选择一个“低碳生命线”点；所有一级医疗任务不变，普通负荷延后边界透明。
5. **碳证据（60秒）**：展示 Carbon-SOC、动作级 MRV 和服务等价闸门；点击一个开关动作追溯到能源流、因子和 ΔCO2。
6. **价值与可信度（45秒）**：输出 C-RSLA/预案复盘包，说明项目是预案级数字孪生决策支持原型；用输入 hash、固定 seed、物理硬校验和失败日志说明结果可复算。

## 6. 申报材料中必须守住的表述

- 说“**极端天气下配电网恢复预案与碳 MRV 决策支持原型**”，不说“已接管真实电网调度”。
- 说“**真实/公开天气回放驱动的、可校准设备脆弱性先验**”，不说“已精准预测某地区设备故障”。
- 说“**在相同医院任务和服务约束下的方案间排放差额**”，不说“恢复电量就是减排”。
- 说“**Carbon-SOC 用于恢复阶段储能来源与环境属性的可追溯归因**”，不说“储能天然零碳”。
- 说“**不通过 P/Q/V、热限、GFM、SOC/燃料、同期/遥控条件的方案被标为不可执行**”，不只展示成功动画。
- 说“**医院任务模型为场景化模板**”，不把合成任务参数包装成真实医院运行数据。

## 7. 最终决策

若只允许选择一个“技术核心”，选 **#2 ε-constraint Pareto + #6 动作级 MRV**：它们共同解决公平性和可核查性。

若只允许选择一个“视觉核心”，选 **#4 成岛能力护照 + #5 医院任务链**：它们把抽象配电网恢复变成“医院生命线是否能活下来”的直观故事。

若只允许选择一个“原创标签”，选 **#1 Carbon-SOC**：但前提是把它做成**调度约束、账本、测试、界面解释四位一体**，否则宁可在材料中明确列为下一阶段。

> **冠军版项目名建议**：
> **GridRescue：面向极端天气医院生命线保供的碳溯源微网恢复与 Pareto 决策数字孪生平台**
