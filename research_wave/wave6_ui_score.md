# GridRescue Streamlit UI：竞赛评委视角审计与 5 分钟导演稿

**审计日期：2026-08-22（北京时间）**  
**范围：** 仅审阅 `app.py`、现有导出物、README 与 Wave 4/6 研究材料；未修改应用代码。  
**判定尺度：** “评委影响”=五分钟内帮助评委形成高分判断的能力（1低–5高）；“认知噪声”=默认首屏/流程中增加理解成本的程度（1低–5高）。

## 1. 总判定

现在的应用已经有**真实可演示的计算闭环**：故障拓扑、三策略、逐时调度、潮流校验、Pareto、孤岛护照和 CareTask。问题不是功能少，而是把“评委要作出的一个判断”切成了八个平级标签页；当前首屏还把六个未带门控语义的 KPI 放在最醒目位置。结果是评委先看到一串结果，后面才逐页找“这些结果是否可靠、是否以少供普通负荷换来、医院任务是否真的过了”。

**应收敛成一个结论链：**

```text
灾害与风险
→ 推荐恢复动作
→ 生命线/物理门是否成立
→ 同服务条件下的碳—韧性权衡
→ 可复算证据与已知边界
```

### 当前最需要避免的“高分杀手”

1. **把 `碳韧协同恢复`默认显示成“推荐/低碳”却没有显式 claim gate。** 当前暴雨固定样例中，其 EENS 为 4,787.7 kWh，高于最小失供的 2,223.1 kWh；两者关键恢复率均为 100%。评委会立刻追问普通服务是否被牺牲。默认 UI 必须用 `同服务门：待核/条件` 或准确门状态约束“低碳”表述，绝不能让绿色 KPI 替代比较资格。
2. **CareTask 与 Pareto 的实现边界必须上墙。** 当前任务级最低功率可进入调度、任务级功率/电压结果可后验检查；但 deadline、持续时长、依赖、任务电压尚未进入 Pareto 资格。界面不能把 CareTask 的绿色任务表和 Pareto 前沿并列后暗示“任务保证的低碳前沿”。
3. **MRV 目前是报告出口，不是证据中心。** 当前 `flood_v04` 等导出目录含网络 manifest、动作/调度/潮流/护照文件，但没有 `run_manifest.json`、`factor_snapshot.csv`、`evidence_index.json`、`seal.json` 或独立 verify 结果。UI 应显示 `DRAFT / unsealed`，并把来源等级与封签状态分开；“SHA-256 源网络”并不等同整个 run 可复算。
4. **图表存在量纲和语义混叠。** 能源图把 `pv_available_kw` 当堆叠“能源来源”视觉上易被读成已供电；潮流图把百分比支路负载率与 pu 电压共用纵轴；三策略图将各指标先按最大值归一化，易掩盖绝对差和正负方向。

## 2. 目标信息架构：从“八个功能页”变成“一个决策工作台 + 三个证据区”

### A. 固定顶部：60 秒内可读完的决策状态条

**标题下、KPI 上必须固定一行：**

```text
[ E 类合成灾害推演 ] [ case33bw 网络输入可追溯 ]
[ Run: live-session / 未封签 ] [ Physical: PASS / BLOCKED / UNKNOWN ]
[ Care contract: PARTIAL / 未接入 Pareto ] [ Comparative claim: LOCKED ]
```

- 每枚 badge 有**文字 + 图标/形状 + 颜色**，颜色只作冗余编码。
- 建议色义：红 `BLOCKED`、琥珀 `CONDITIONAL`、绿 `PASS`、灰 `UNKNOWN`、蓝 `RUNNING`。禁止把 E 类合成、未封签或“只后验检查”的项目涂绿。
- 顶部右侧只保留一个强结论卡：`推荐策略：碳韧协同（条件推荐）`，其下必须列出 **因为何种 gate 才允许/不允许推荐**。若 gate 未实现，文案改为 `当前查看策略`。

### B. 首屏主区：决策工作台（默认页，约 90 秒）

**左 2/3：动态拓扑；右 1/3：事件—动作—生命线。**

1. **灾情条（拓扑上方，单行）**：`暴雨内涝 · L6/L13/L27 故障 · PV -62% · 抢修 46 km · T+0h`。点击才展开场景说明，默认不占纵向空间。
2. **网络图**：保留现有拓扑，但强化当前小时 marker、故障线、闭合联络线、医院/关键节点图例和节点选择。节点 hover 显示 `Node / critical tier / energized / island ID / task count`，而不是只给负荷参数。
3. **右栏上半：“此刻该做什么”**：仅显示下一项关键动作、对象、开始时刻、目的、状态（`SIMULATED_APPLIED` 而非“已完成/现场执行”）、一个“查看潮流证据”入口。
4. **右栏下半：“生命线合同”**：Tier-1 任务通过数、最早 deadline、当前阻塞任务数；一张最多 4 行的任务小卡，而不是完整 data frame。点击进入任务详情抽屉。

### C. 第二层：只保留三块导航，而不是八个同权 tab

1. **决策对照**：三策略同输入 + Pareto + 推荐理由 + 鲁棒性摘要。
2. **运行证据**：能源/碳流 + 潮流/最弱约束 + 成岛护照，以“当前小时”共同联动。
3. **审计与导出**：MRV、数据质量、输入来源、下载与边界。

CareTask 不应独立成为与拓扑平级的“功能岛”；它是首页右栏和“决策对照”服务门的详情。成岛护照也不应先让评委看一张全量表，而应成为“运行证据”里的空/黄/红异常解释。

## 4. 视觉编码规则（必须统一）

### 状态与证据

| 语义 | 主编码 | 辅编码 | 允许的文案 |
|---|---|---|---|
| 通过 | 绿 + 实心圆 | `PASS` / `READY` | 已通过**当前模型门控** |
| 条件通过 | 琥珀 + 三角 | `CONDITIONAL` | 假设/证据限制见详情 |
| 阻断 | 红 + 八角/叉 | `BLOCKED` | 不显示推荐或减排结论 |
| 未知 | 灰 + 问号 | `UNKNOWN` | 缺少何种输入或能力证据 |
| 推演中 | 蓝 + 进度 | `RUNNING` | 显示缓存/预计完成，不显示零值 |
| 合成数据 | 紫灰 + `E` | `SYNTHETIC` | 合成模板，不是现场测量 |

### 数值语义

- **绿色不等于更小。** EENS/排放/柴油用“向下改善箭头”；服务恢复率/安全裕度用“向上改善箭头”。
- 所有 delta 都必须带比较对象，例如 `vs 最小失供：+2,565 kWh EENS`，并附 gate 状态。
- 指标精度：功率 0–1 位；电压 3 位；排放 0–1 位；hash 12 位；避免展示大量小数制造“伪精确”。
- 拓扑颜色以外再用线型：故障=红虚线+叉，闭合联络=青粗实线，备用联络=灰点线，已带电=绿节点，关键节点=节点外圈/十字图标。

## 5. 可被评委相信的 evidence badges

### 顶部最小 badge 组

```text
场景：E-SYNTHETIC      网络：case33bw / source hash ✓
运行：LIVE SESSION · UNSEALED
物理：PASS | 当前策略/全时段
任务：PARTIAL | task audit；未作为 Pareto 资格
比较：LOCKED | 服务等价/数据质量未封存
```

这套文案比“可信/已验证”更强，因为它让评委看见系统知道自身边界。实际接入 `seal.json` 后才显示：

```text
RUN 20260822-xxxxxx · SEALED · verify-run PASS
Factors: CONDITIONAL (D/E) · Comparative claim: CONDITIONAL
```

### 证据卡的四层追溯

1. **输入**：场景 definition、network snapshot、资源/负荷、因子快照、seed。
2. **动作**：`action_id`、目标、前后状态、仿真状态、理由。
3. **约束**：调度时段、潮流节点/支路、孤岛/任务结果、失败原因。
4. **结论**：策略指标、比较 gate、报告、hash/evidence index/seal。

当前尚没有结构化 action ledger 时，动作卡必须显示 `planned simulation action`，而非“执行完成”；当前尚无 run seal 时，下载区的状态是 `exported / unsealed`。

## 6. 失败、空、加载状态：把诚实失败变成可信度资产

| 状态 | 默认视图应显示 | 一键去向 |
|---|---|---|
| 当前小时无动作 | `T+Nh 无新增离散动作；沿用上一恢复状态` + 下一关键时刻按钮 | 跳到 next action hour |
| 当前没有非根孤岛 | `无独立运行岛；此时所有带电分量与上级连通` | 跳到最早出现 island 的小时 |
| 非根岛 GFM/黑启动证据未知 | `UNKNOWN：模型容量存在，现场能力台账缺失` | 显示缺失字段清单 |
| 潮流越限或不收敛 | 红色 `BLOCKED` + 最弱 node/branch/hour + 违反类型 | 回到该小时拓扑 |
| Tier-1 任务失败 | 红色任务卡 + 失败码、deadline、功率/电压事实 | 跳任务详情与潮流 |
| CareTask 未纳入 Pareto | 黄色 `PARTIAL` | 显示“任务后验评价；不可用于任务保证声明” |
| 无可行 Pareto 点 | `当前服务/物理合同下无可推荐点` | 展示淘汰点及失败原因 |
| 未封签/因子未冻结 | 灰/黄 `UNSEALED` / `CONDITIONAL` | 展示缺少 manifest、factor snapshot、verify |
| 缓存/求解中 | skeleton + `正在读取固定快照/预计 n 秒` | 不显示空图或 0 KPI |

演示建议主动展示一次**N03 或某任务的 BLOCKED**、一次**成岛 `UNKNOWN`**。这比全绿大屏更能打消“演示数据挑过”的怀疑。

## 7. 5 分钟交互流（只需 11 次动作）

**会前固定：** 演示模式、暴雨内涝、碳韧协同、T+0、预计算 Pareto/护照/任务快照均已加载。只在问答时退出演示模式；不现场跑 Pareto、蒙特卡洛或打开全量 CSV。

| 时间 | 操作 | 屏幕必须回答 | 说辞锚点 |
|---:|---|---|---|
| 0:00–0:20 | 停在首页，读状态条与灾情条 | 这是何种事件、哪些结论目前有/没有资格 | `先保生命线与物理，再比较碳。当前为 E 类合成预案推演。` |
| 0:20–0:45 | hover L6/L13/L27；拓扑仍为 T+0 | 三处故障如何把风险传到关键节点 | `同一灾害、资源、网络输入供三种策略对照。` |
| 0:45–1:10 | 打开“决策对照” | 为什么传统/单目标不是自然推荐 | 展示绝对 EENS、关键服务、排放和 gate；不讲归一化柱图。 |
| 1:10–1:35 | 点 Pareto 的候选点/推荐理由 | 低碳是否靠少供换来的 | `服务、物理与任务 gate 未过，点保留但不给推荐/减排标签。` |
| 1:35–2:00 | 回首页，小时跳至首次关键修复（如 T+7）并点 action | 动作怎样改变拓扑 | `这是仿真采用动作，目标、时刻、潮流证据可追溯。` |
| 2:00–2:30 | 点医院任务小卡 | “关键负荷”具体是什么 | 先 CORE/ICU/急诊等任务，再看 kW、deadline、V 与依赖。 |
| 2:30–2:50 | 展示一个 BLOCKED 任务 | 系统会不会用总体恢复率掩盖失败 | 展示 failure reason 与反向跳转。 |
| 2:50–3:20 | 进入运行证据，选岛/当前小时 | 这个孤岛是否真实可独立运行 | `READY/CONDITIONAL/BLOCKED/UNKNOWN` + 最弱约束；未知不涂绿。 |
| 3:20–3:45 | 同页潮流与能源联动 | 物理和碳从何而来 | V、loading、能源来源、SOC 分开讲；电池放电不当负排放。 |
| 3:45–4:20 | 审计与导出 | 一项数字如何回放 | 输入→动作→dispatch/潮流→报告；当前未封签就明确未封签。 |
| 4:20–5:00 | 展开鲁棒性摘要，回首页收束 | 是否只是单个漂亮剧本 | 显示完成数、分位数和失败样本；以“可看、可验、可复算”的边界收束。 |

## 8. 精确 cut / add 清单

### P0：答辩前必须做

- **Cut**：默认并列八个 tab、归一化三策略柱图、潮流双量纲同轴图、未供电与 SOC 同轴图、所有全量 dataframe 的首屏出现。
- **Add**：全局 run/gate/source 状态条；`当前策略`与`推荐资格`分离；任务小卡+失败原因； Pareto 的 task/physical/claim 状态编码；岛护照热图+当前异常卡；MRV 的 `UNSEALED` 真实状态。
- **Add**：演示模式（固定 scenario/strategy/hour/预计算 artifact）；探索模式把重计算放次级入口。
- **Add**：任何“查看证据”跳转都携带 scenario、strategy、hour、node/island/action 上下文。

### P1：明显提升评分但可后置

- action ledger 的稳定 ID、动作前后状态与 evidence refs；下载组含 manifest/factor snapshot/evidence index/seal/verify。
- 当前小时 marker 同步所有时间图；一键跳至下一个关键动作、最弱约束和失败任务。
- 三策略的 P50/P90/失败原因折叠区；明示它是合成扰动结果。
- Carbon-SOC 来源桶图，未知初始 SOC 灰显。

### P2：不应挤占展示时间

## 9. 交付验收（界面层）

1. 评委在 **10 秒**能读到：场景、当前策略、生命线/物理/比较资格、数据等级。
2. 评委在 **60 秒**能读到：哪个动作改善什么、为什么不能仅看碳总量。
3. 每个绿色推荐元素都能点击到相应 gate；任一 gate 缺失时显示黄/灰/红而非绿色。
4. 点击一项动作、任务、岛或 Pareto 点后，最多两步能回到对应潮流/调度/输入证据。
5. 截图中不出现“E 类合成、未封签、任务未进入 Pareto”被绿色样式掩盖的情况。
6. 页面宽屏下首屏不出现需滚动才能看全的六张 KPI + 图例 + 核心动作；核心动作和生命线卡必须与拓扑同时可见。

**一句话评委版本：** GridRescue 最高分的 UI 不是把所有模型结果全展示，而是让评委在五分钟内沿着“故障—动作—生命线—物理—碳—证据”验证一个有边界、可追溯的决策。
