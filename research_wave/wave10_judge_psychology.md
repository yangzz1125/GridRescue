# GridRescue Wave 10：一等奖评委决策心理与工作台收敛报告

**正式日期：2026-08-22**  
**范围：** 只读研判 research_wave/wave8_synthesis.md、README.md、docs/competition_narrative.md（申报书初稿）、app.py，并吸收既有 Wave 8/9 评审结论；本报告不修改生产代码。  
**目标：** 以一等奖评委的“30 秒判断—3 分钟信服—追问可回查”心理路径，把八个同权 Tab 收敛为一个可信决策工作台。

---

## 1. 结论先行：评委要的是“有资格被推荐”的决定

GridRescue 已具备 CareTask 服务合同、P/Q 潮流和成岛门、Pareto 服务预算、MRV bundle/claim gate/seal/verifier，以及三灾种三策略。当前主要减分点不在功能数量，而在评委必须跨八个 Tab 自己拼出因果链：

灾害影响 → 候选选择 → 服务是否守住 → 物理是否成立 → 碳差对应什么服务代价 → 证据是否可复算 → 推荐/拦截。

一等奖版本应把首页从“选策略后看指标”改成“系统给出推荐，并同时给出推荐资格、服务代价和复核入口”。

> 首页只回答：当前冻结场景和时刻，哪个候选可推荐；它通过了哪三道门；它以什么服务代价对应什么清单差；评委如何在 10 秒内复核。

### 当前界面观察

1. 当前六个 KPI 随 sidebar 的“恢复策略”直接切换，首屏先诱导比较算法数值，不先说明推荐资格。
2. 八个 Tab 同权排列：数字孪生、三策略、能源碳流、潮流、MRV、Pareto、成岛、生命线。每页合理，合在一起却增加评委的认知拼图成本。
3. MRV 已有实时复核、seal、文件数、factor class、same-service gate、claim status；但它在第 5 个 Tab，最有价值的可信度证据不在主路径。
4. Pareto 当前可现场计算 0/4/5/6% 点，而归档 claim gate 可能对应不同普通服务预算。演示交互结果与冻结主证据必须分层，否则会被质疑口径漂移。
5. README 与 Wave 8 已明确边界：当前使用 kgCO2、E 类合成工程假设；same_service_pass=false 时只表达“受控服务预算下的清单差异”。这些边界要变成界面行为，而非页脚文字。

## 2. 评委心理模型：三个时间窗口

| 时间窗口 | 评委潜台词 | 工作台必须给出的答案 | 证据 |
|---|---|---|---|
| 0–30 秒 | “你解决什么，推荐谁，是否靠少供电刷低碳？” | 推荐结论、三门状态、普通服务代价、数据等级 | 结论带 + 两候选对照 |
| 30–180 秒 | “这不是大屏拼图吗？为何可信？” | CareTask、P/Q/电压/热限、成岛拦截、MRV 完整性 | 三个证据抽屉 + 被拦截反例 |
| Q&A | “数字从哪来、边界在哪、如何验证？” | run ID、因子快照、claim gate、verified、失败码、下载 | 证据索引、hash、ZIP |

评委不需要第一眼看完所有图；他们需要第一眼看见系统主动拦截错误结论。这比增加图表更有技术记忆点。

## 3. 目标信息架构：8 Tab → 1 工作台 + 3 证据抽屉 + 1 追问库

### 3.1 新结构

    常驻证据控制条
      ├─ 冻结演示预设：主推荐 / 被拦截反例 / 稳健性追问
      ├─ 场景、时刻、候选（默认锁定主证据 run）
      └─ run ID · 数据等级 · SEALED · Verification · 导出

    决策工作台（默认）
      ├─ 结论带：推荐/不推荐 + 服务门/物理门/证据门
      ├─ 行动画布：拓扑、故障、带电、联络、关键服务节点、共享小时游标
      ├─ 推荐理由：服务合同、Vmin/loading、碳清单/普通 EENS 增量
      ├─ 两候选决策条：服务锚点 vs 受控服务预算候选
      └─ 当前动作时间线：动作—影响—理由—状态

    证据抽屉
      ├─ 服务：CareTask、deadline、功率/电压、失败码
      ├─ 物理：Vmin/loading、成岛护照、BLOCKED/DEGRADED 原因
      └─ 碳与 MRV：活动→因子→清单、claim gate、seal、verify、下载

    追问库
      └─ 三策略全表、完整 Pareto、压力测试、原始 CSV、方法与真实接入路线

### 3.2 八个现有 Tab 的去向

| 现有内容 | 收敛后位置 | 现场角色 |
|---|---|---|
| 恢复数字孪生 | 工作台行动画布 | 主舞台，默认可见 |
| 三策略对照 | 两候选决策条；完整表进追问库 | 先解释“为何推荐” |
| 能源与碳流 | 碳与 MRV 抽屉 | 解释清单组成 |
| 潮流校验 | 物理证据抽屉 | 给 Vmin/loading 与失败理由 |
| MRV 报告 | 常驻状态 + 碳与 MRV 抽屉 | 顶层可信度 |
| 公平 Pareto | 两点决策条；完整扫描进追问库 | 显示服务代价，防绿洗 |
| 成岛护照 | 物理抽屉 + 拦截反例预设 | 反假可行证据 |
| 生命线任务 | 服务抽屉 | 证明关键负荷不是权重标签 |

### 3.3 首页约束

- 首屏关键数字最多 6 个：候选清单差、普通 EENS Δ/预算、CareTask 完成、Vmin、最大载流率、Verification。
- 每个碳数字同屏携带 kgCO2、比较对象、普通服务代价、claim status。
- “E 类合成工程输入 / 预案级公开算例”常驻。
- 默认不触发耗时 Pareto 计算；现场使用冻结数据，求解入口降为研究模式。
- 默认选“主推荐”预设，而不是先让评委选三种策略。

## 5. 决策工作台屏幕脚本

### 顶部常驻证据条

    GridRescue｜预案级公开算例｜case33bw｜E 类合成工程输入
    [暴雨内涝] [T+04h] [主推荐▼]       run-XXXX | SEALED | VERIFIED PASS | 导出证据包

左侧说明边界；中央只留场景、时刻、预设；右侧放可信性入口而非普通设置项。

### 结论带

    推荐：受控服务预算下的可执行候选
    [服务门 PASS] [物理门 PASS] [证据门 PASS]
    候选-参考清单差：-X kgCO2 ｜ 普通 EENS：+Y kWh（epsilon=Z%）
    CareTask：4/4 ｜ Vmin：0.xxx pu ｜ 最大载流率：xx%
    主张：受控服务预算下的运行碳清单差异（非严格同服务降低）

颜色：绿=可推荐，黄=受控让步或 E 类边界，红=BLOCKED/FAIL，灰=未验证或非当前候选。

### 中央画布与理由

左侧继续使用现有网络图，但加入 CareTask 节点图层，并由小时游标驱动。右侧只保留三句可点击理由：

1. 服务合同：任务完成数、最严任务电压、deadline。
2. 物理可行：通过小时数、Vmin、最大载流率。
3. 碳与证据：清单差、普通服务预算、bundle 现场复核 PASS。

### 底部两候选决策条

首屏只比较服务锚点（0%）与受控预算候选。前者展示更强普通服务，后者展示医院/关键服务合同不变、普通 EENS 增加和对应清单差。完整 Pareto 留在“展开全部前沿”。

## 7. 不建议做的伪升级

1. 不增加第九个 Tab；问题是页面平权和叙事分散。
2. 不把 AI、3D、地图、区块链放首页；它们不提高三门可信度。
3. 不让现场 Pareto 求解承担主线；展示应是冻结、可复核的决定。
4. 不把 same_service=false 的负清单差包装为“减排”。
5. 不把 case33、合成任务、E 类因子说成真实调度或第三方核证。
6. 不重做大规模 MISOCP 或 Carbon-SOC 来赌深度；十天内证据可见性、反例、口径一致和答辩路径收益更高。

## 8. 最终行为验收

### 30 秒
- 无需切页即读到推荐、三门、碳差、服务代价、数据等级、run/verify。
- 评委能复述：“系统不是直接报低碳，而是先过服务、物理、证据三门。”
- 页面不存在孤立的“碳排更低”绿色大数字。

### 3 分钟
- 主推荐预设 → CareTask → 两候选 trade-off → BLOCKED 反例 → MRV PASS。
- 不触发长时计算；只使用一个冻结主 run 的数字。

### 尖锐追问
- “少供电换碳？”：D04/D10/D21，普通 EENS Δ、epsilon、claim gate 同屏。
- “为何可信？”：D03/D13/D15，任务、P/Q、Vmin/loading、因子和 verifier。
- “是否假可行？”：D07/D14，NO_GFM、最弱约束、失败留痕。
- “是否挑好案例？”：D20，样本、失败、replay。
- “如何接真实业务？”：D24，网络、资产、任务、因子四类输入替换路径。

## 9. 一等奖级展示口径

> **GridRescue 的创新不是再给恢复优化加一条碳曲线，而是把生命线服务合同、电网物理可行和可复算证据设为推荐门槛：任何方案没有通过三道门，就没有资格把更低的碳数字展示给决策者。**
