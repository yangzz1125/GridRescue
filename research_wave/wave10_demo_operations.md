# GridRescue 竞赛演示运行保障方案（Wave 10）

- **项目**：碳韧智网 GridRescue V08
- **文档日期**：2026-08-22
- **适用对象**：Streamlit 学术竞赛原型、现场路演与评委追问演示
- **目标**：将现场演示从“依赖一台能联网的开发机”改造成可离线、可复原、可审计、可在故障时平稳降级的展示包。
- **边界**：本文只定义演示运行、封存、复核和应急动作；不修改模型、算法、数据或生产代码。

---

## 1. 运行基线与演示原则

GridRescue 当前可用基线是 V08：`release_manifest_v08.json` 的冻结日为 **2026-08-22**，记录 46 项测试通过（`python -m pytest -q`）、三套正式封存场景（暴雨内涝、台风、极端高温）以及三套已验证 MRV 包。现场默认主场景固定为**暴雨内涝**；台风与高温仅用于评委追问时的备用切换。

演示只陈述已封存、已校验的结论：MRV `SEALED` 仅表示文件完整性和内部重算通过；因子数据为 E 类合成工程假设；当前碳韧策略的主张状态是 `controlled_service_budget_inventory_difference`，不表述为严格同服务减排。现场不运行长时蒙特卡洛、重新生成封存数据或修改参数来追逐“更好看”的数值。

**三层故障隔离：**

1. **主路径（Live）**：离线启动的 Streamlit App，读 V08 冻结数据；
2. **同构路径（Replay）**：本机录屏 MP4、逐帧截图和只读 CSV/MRV ZIP，内容与主路径按同一点击顺序组织；
3. **证据路径（Static）**：纸质/本地 PDF 摘要、`release_manifest_v08.json`、各场景 MRV `verification.json` 与 SHA-256 清单。

任意一级故障发生后，主持人立即切换下一层，不在投影幕上排障超过 30 秒。

**建议启动脚本（作为演示包内受控文件）**：

```powershell
# start_demo.ps1（示意；打包时将 $Root 固化为真实演示目录）
$ErrorActionPreference = 'Stop'
$Root = Split-Path -Parent $MyInvocation.MyCommand.Path
Set-Location $Root
$env:PYTHONPATH = "$Root\src"
$env:STREAMLIT_BROWSER_GATHER_USAGE_STATS = 'false'
$env:STREAMLIT_SERVER_HEADLESS = 'true'
$env:STREAMLIT_SERVER_ADDRESS = '127.0.0.1'
$env:STREAMLIT_SERVER_PORT = '8501'
& "$Root\.venv\Scripts\python.exe" -m streamlit run "$Root\app.py" `
  --server.address 127.0.0.1 --server.port 8501 --server.headless true
```

使用方式：从演示根目录启动 `powershell -ExecutionPolicy Bypass -File .\start_demo.ps1`；浏览器只访问 `http://127.0.0.1:8501`。若 8501 被占用，恢复脚本优先关闭遗留的本机 Streamlit/Python 进程，再重启；不临场改端口或改 App 配置。

## 4. 冻结演示包结构与完整性

建议交付三份完全相同的 `GridRescue_V08_Demo_20260822.zip`：主机本地、备机本地、加密/封签 U 盘。ZIP 目录结构如下：

```text
GridRescue_V08_Demo_20260822/
├─ app.py
├─ src/  data/  artifacts/v08_official/
├─ README.md  requirements.txt  release_manifest_v08.json
├─ start_demo.ps1  recovery_demo.ps1  STOP.md
├─ .venv/ 或 wheelhouse/                 # 按离线部署选一种
├─ evidence/
│  ├─ DemoEvidence.zip
│  ├─ sha256sums.txt
│  ├─ judge_qna_index.md
│  ├─ claims_card.pdf
│  ├─ screenshots/01_home.png ... 08_mrv_zip.png
│  └─ replay/whole_demo_5min.mp4, pareto_click.mp4, mrv_verify.mp4
└─ logs/demo-start.log  logs/demo-recovery.log
```

### ZIP 封装规则

1. 由同一台已验证设备生成 ZIP；生成后对 ZIP 本身和内部每个文件各算一次 SHA-256。
2. `sha256sums.txt` 使用相对路径、UTF-8、稳定排序；首次校验后设只读。
3. ZIP 外另放一个短清单（纸质/手机离线副本）：ZIP 文件名、字节数、SHA-256 前后各 8 位、生成时间、保管人。
4. 封存前运行 `python -m pytest -q`，并分别运行三个已有 MRV bundle 的 verifier；只保存输出，不改变封存内容。
5. 将正式清单中的 `release_manifest_v08.json` 键文件哈希与当前母包逐项比对；任一不一致即重新建立包，禁止现场继续使用旧证据宣称 V08。

**PowerShell 完整性检查示例：**

```powershell
$root = 'C:\Demo\GridRescue_V08_Demo_20260822'
Get-FileHash "$root\release_manifest_v08.json" -Algorithm SHA256
Get-FileHash "$root\evidence\DemoEvidence.zip" -Algorithm SHA256
Get-FileHash "$root.zip" -Algorithm SHA256
Get-Content "$root\evidence\sha256sums.txt"
```

## 6. 恢复 SOP（台上可执行版）

### 6.1 App 页面异常

1. 主讲人继续当前句，不读异常文本；运行官记录 `HH:MM:SS / 页面 / 现象`。
2. 运行官仅做一次：刷新浏览器或关闭标签并重新打开 `http://127.0.0.1:8501`。
3. 若 10 秒内无主页面，运行 `recovery_demo.ps1`（结束遗留本机服务后调用 `start_demo.ps1`）。
4. 若从故障出现起满 30 秒，主讲人说“我切到同一冻结证据的回放”，立即打开对应 MP4 或 PNG；台上不继续调试。
5. 结束后保留日志并在赛后再查根因。

### 6.2 Pareto 或图表迟滞

1. 等待上限 10 秒；不连续点击，不切换场景。
2. 播放 `pareto_click.mp4`，画面与讲稿维持同一口径；再展示 `06_pareto.png`。
3. 若被追问，打开封存 `pareto` CSV/MRV 目录，而不是再次计算。

### 6.3 投影/线缆/供电异常

1. 主讲人停止点击，语言转为口径卡的三条事实；场务检查投影输入源和线缆。
2. 30 秒内恢复则继续当前画面；超过 30 秒，备机接同一投影，或使用备机屏幕/纸质摘要完成陈述。
3. 主机崩溃不连接公共网络、不启动更新；由备机接管。

### 6.4 证据下载或文件打开异常

1. 改用 `evidence/DemoEvidence.zip` 与预先导出的截图/CSV。
2. 用 `Get-FileHash` 展示 ZIP 和 `release_manifest_v08.json` 哈希，必要时展示已打印摘要。
3. 不临场改 ZIP、重新封存、修改 `verification.json` 或补填数值。

## 9. 结束状态与赛后留档

演示完成后不覆盖冻结母包。运行官保存启动/恢复日志；证据官记录最终使用的包名与哈希、是否发生切换、切换时间和展示的回放文件。赛后复盘可从复制件分析故障，但不得将临场日志、浏览器缓存、改动后的数据反写到 `artifacts/v08_official/` 或重新标记为 2026-08-22 的冻结证据。

**最终判断：**竞争演示的可靠性来自“Live 可跑、Replay 同构、Static 可核验”的三层结构，而不是假定现场网络、投影、浏览器和实时计算永远正常。V08 的评分价值在于服务合同、潮流可行性和 MRV 证据链；故障时守住这三条证据，展示仍然成立。
