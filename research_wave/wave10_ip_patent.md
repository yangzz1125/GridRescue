**正式日期：2026年8月22日**  
**对象：** \`work/gridrescue\` 中“碳韧智网 GridRescue”研究生低碳配电网恢复软件原型  
**性质：** 内部技术与知识产权准备建议；基于仓库现状形成，不构成新颖性检索结论、自由实施（FTO）意见、申请已提交或专利已获授权的声明。

## 一、结论先行

GridRescue 最值得封装的资产不是“又一个配电网恢复优化器”，而是把以下四件技术对象闭合为一套**可执行、可拒绝、可追溯的恢复推荐机制**：

1. **生命线服务合同**：把医院/关键服务的节点、最低功率、时间窗、截止时间、连续供电、依赖和电压条件写成可计算约束，而非静态权重；
2. **恢复—调度—潮流反馈**：候选拓扑与节点级资源调度需经过 P/Q 潮流、热限、电压、孤岛供源及 SOC 反馈；物理失败的候选不进入推荐集；
3. **先锁服务、后比较碳的准入机制**：医院、其他关键、普通服务分层词典序锚定；普通服务让步只在公开 \`epsilon\` 预算内发生；
4. **结果证据包与主张门**：输入、因子、活动账、排放清单、动作链、代码包 hash、验证结果和“严格同服务/受控服务/仅清单”主张状态同步输出。

**推荐的首件发明方向**：  
> **一种基于生命线服务合同、物理反馈与证据门控的配电网灾后低碳恢复方法、装置、设备及存储介质。**

该方向比“碳排最小化恢复方法”更有区分度，也能由当前原型的 \`care.py\`、\`dispatch.py\`、\`pipeline.py\`、\`powerflow.py\`、\`pareto.py\`、\`mrv.py\` 形成较完整的实施例。其申请重点应落在**面向实际电网对象的约束建模、物理校验、候选淘汰和控制/恢复指令生成**上；MRV hash 链适合作为从属特征和第二件专利，不宜让“文件存证”单独承担首件独立权利要求的技术性。

**准备策略**：一主两辅、软著先行、十天内完成可交代理人的高质量交底包。

- **主专利 A（优先）**：服务合同门控的低碳恢复方法；
- **辅专利 B**：面向离网孤岛的成网能力护照与恢复准入方法；
- **辅专利 C**：面向恢复行动的 MRV 证据链、主张等级判定与独立复算方法；
- **软件著作权**：先以完整软件产品确权；对可独立交付的 MRV verifier、CareTask 服务合同评估器、成岛能力护照组件再做模块化登记评估。

当前材料支持“具备专利交底基础”的判断，**尚不支持任何“已检索无冲突”“必然授权”“已经申请/登记”表述**。

### 2.2 当前边界必须写清

1. 网络基础数据来自 MATPOWER \`case33bw\`；DER 位置、关键负荷类别、热限、因子与 CareTask 是工程/赛事合成假设。
2. 当前为 24 个一小时时段；README 已明确 \`time_step_h=1.0\` 的适用边界。
3. 物理层为径向配电网 P/Q 前推回代及反馈闭环，不应表述为已完成统一 MISOCP 或完整 AC-OPF 最优求解。
4. MRV verifier 证明的是文件完整性、引用一致性和方程复算；不等同于实测、第三方核证或法定碳核查。
5. 岛屿 GFM/黑启动目前是模型假设或字段化证据，不应改写成现场调试/并网认证结果。
6. 这些边界不削弱可专利性；它们决定说明书中“仿真实施例”“真实馈线实施例”和“数据质量门”的写法。

## 五、推荐首件专利的一页交底纲要

### 5.1 建议名称

**一种基于生命线服务合同、物理反馈与证据门控的配电网灾后低碳恢复方法、装置、电子设备及存储介质**

### 5.2 技术问题

现有灾后配电网恢复方案常以失供电量、恢复时间或碳排的单一/加权目标求解。其不足包括：

- “关键负荷优先”往往只是固定权重，无法判断具体医院/通信/冷链任务是否满足功率、时限、连续性、依赖及电压要求；
- 候选恢复策略可能只在优化模型中可行，未将实际节点拓扑、孤岛供源、无功、电压、热限、线损和 SOC 反馈纳入最终准入；
- 方案之间的碳比较可能因供电服务不同而失真；
- 恢复动作、因子、活动量和结果之间缺少可机读的一致性证据，导致控制建议难以复核。

### 5.3 核心技术方案（独立权利要求的骨架）

一种配电网灾后低碳恢复方法，包括：

1. 获取配电网的节点、支路、联络开关、故障状态、可控电源/储能参数、负荷时序以及灾害修复参数；
2. 获取至少一个生命线服务任务，每个任务包括关联节点、最低供电功率、任务窗口、截止时刻、连续供电时长、任务依赖关系和电压阈值；
3. 基于故障状态生成候选恢复拓扑与恢复动作序列，并在节点—时段—连通分量尺度上生成包含分布式光伏、储能、柴油机和/或上级电网的资源调度候选；
4. 按服务层级计算医院任务、其他关键任务和普通负荷的服务锚点；针对给定普通服务预算，将医院和其他关键服务锚点作为约束，并在所述预算内对候选的恢复阶段碳排进行求解；
5. 对每一候选执行潮流校验，得到节点电压、支路负载率、无功平衡、网络损耗、孤岛供源状态和储能状态；依据潮流校验结果更新所述资源调度或服务上限并迭代；
6. 根据节点级供电结果和潮流结果对每个生命线服务任务进行功率、电压、连续性、截止时间和依赖验证；
7. 当候选同时满足服务合同和物理约束时，生成含恢复动作序列、资源调度指令、碳排清单及证据索引的恢复推荐；当任一验证失败时，将候选标记为阻断并输出对应失败原因。

### 5.4 建议的从属权利要求层级

| 层级 | 从属主题 | 可写入的限定 |
|---|---|---|
| L1 | 服务合同表达 | 任务窗口、最低功率、deadline、连续时长、依赖、最小/最大电压 |
| L2 | 并发任务 | 同一节点多个活跃任务的累计最低功率约束 |
| L3 | 分层服务锚点 | 医院→其他关键→普通负荷的词典序锚定 |
| L4 | 服务预算 | 普通负荷未供电量上限为基准服务锚点加公开 epsilon 预算 |
| L5 | 空间调度 | 按节点、时段及连通分量设置能量平衡与资源约束 |
| L6 | 成岛判定 | 无成网电源、容量不足、无功不足、SOC不足或电压/热限越界时阻断 |
| L7 | 物理反馈 | 将潮流损耗、组件供电上限或无功约束回灌至下一次调度求解 |
| L8 | 碳清单 | 对购电、柴油、抢修车辆、网损活动量按版本化因子形成时段清单 |
| L9 | 证据索引 | 输入快照、任务定义、动作状态、活动账、因子快照和结果文件的 hash/引用一致性校验 |
| L10 | 失败可解释 | 输出失败阶段：求解、服务合同、潮流、电压、热限、孤岛供源或证据校验 |
| L11 | 装置 | 数据获取模块、候选生成模块、调度模块、反馈校验模块、任务验证模块、推荐生成模块 |
| L12 | 设备/介质 | 处理器执行上述方法的电子设备、计算机可读存储介质和程序产品 |

### 5.5 技术效果应如何写

- 在灾害故障下减少“优化上可行、物理上或生命线任务上不可执行”的候选进入恢复推荐；
- 在服务目标被锁定或明确预算约束后，使碳清单比较具有可解释的服务边界；
- 通过节点级功率与潮流双证据识别任务失效原因；
- 将恢复动作、资源调度、碳活动和输入版本关联，使同一恢复事件可被重复计算和一致性核验。

避免把技术效果写成“碳交易合规”“提高管理效率”“方便领导决策”等单纯管理或商业效果。

## 六、权利要求布局与申请组合

### 6.1 主件 A：服务合同门控恢复

- **独立方法权利要求**：按第5节的七步骤；
- **独立装置权利要求**：围绕数据、候选、反馈、服务验证、推荐生成模块；
- **独立设备/介质权利要求**：覆盖软件实现载体；
- **实施例 1**：IEEE 33 节点暴雨内涝；
- **实施例 2**：台风多支路故障和 PV 降额；
- **实施例 3**：极端高温负荷上升和储能 SOC 约束；
- **对比例**：传统顺序、最小失供、无服务合同门控、无物理反馈或无任务电压证据的方案。

### 6.2 辅件 B：孤岛能力护照

建议名称：  
**一种基于成网能力证据和时序约束的配电网孤岛恢复准入方法**

独立主题：对每个非根连通分量形成跨时段 episode，融合 GFM/黑启动状态、可用有功无功容量、SOC、负荷、节点电压和支路热限，输出 BLOCKED/DEGRADED/CONDITIONAL 状态及最薄弱约束，并作为拓扑恢复候选的准入条件。

### 6.3 辅件 C：恢复事件 MRV 证据核验

建议名称：  
**一种面向配电网灾后恢复方案的碳活动证据链生成与一致性核验方法**

独立主题：把恢复动作状态、活动数据、版本化排放因子、时段清单、输入快照及代码版本建立引用/hash/方程核验关系，对不满足服务或物理 gate 的结果限制其主张等级。  
注意：该案最容易落入“数据处理/管理规则”争议，需强调其与配网拓扑状态、调度动作和实际能量活动量的技术数据耦合。

### 6.4 申请次序

1. 在公开论文、答辩视频、开源仓库、竞赛材料对外披露前，先完成主件 A 的交底与申请决策；
2. 若预算允许，同日或紧邻日期提交 A 与 B；C 可在补足“技术数据闭环”后提交；
3. 若主件 A 的检索显示宽权利要求风险高，仍保留 B 的较窄、工程化的孤岛准入主题；
4. 论文、比赛、GitHub README 和演示视频对外版本均采用“专利申请中/拟申请”的准确状态；在未提交前，只写“已形成专利交底材料”。

## 七、新颖性、创造性和实施充分公开的主要风险

### 7.1 新颖性风险

| 风险源 | 可能覆盖的已知技术 | 对策 |
|---|---|---|
| 配电网服务恢复 | 故障隔离、联络线重构、最小失供、关键负荷恢复、微网成岛。 | 不用“恢复方法”泛化表述；绑定 Task 合同、节点级任务验证、物理反馈淘汰。 |
| 多目标与低碳调度 | 加权碳—可靠性、Pareto、epsilon-constraint、储能/柴油调度。 | 不把优化目标或权重当创新；突出服务锚点先锁定、预算透明和物理/任务双 gate。 |
| 潮流回代/AC 校验 | OPF、前推回代、迭代损耗补偿、配网电压热限校验。 | 说明反馈结果如何改变服务上限和候选准入，而不单主张“做潮流”。 |
| 微网成岛校验 | 黑启动、GFM、储能 SOC、无功和孤岛供电能力。 | 保护 episode 护照、最弱约束识别、恢复拓扑准入的组合。 |
| 区块链/hash/MRV | 日志 hash 链、数据完整性、排放核算、审计报表。 | 将其限定为恢复动作状态、节点化能量活动、服务/物理 gate 和独立复算。 |
| 数字孪生/可视化 | 态势展示、what-if、平台架构。 | 仅作系统实现与软著；不要单独以 dashboard 作为发明核心。 |

### 7.2 创造性风险

最可能的审查意见是：把已知的“恢复优化 + 关键负荷优先 + 潮流校验 + 碳核算”并列拼接，技术人员可直接想到。应提前准备以下论证：

- **共同技术问题**：防止低碳恢复建议在生命线任务和电网物理层面失效，且防止服务不等价造成的碳比较失真；
- **互相作用**：CareTask 不是后处理报表；其最低功率和并发需求进入调度硬约束，且验证需引用潮流电压；潮流反馈又会改变调度可服务上限；只有二者通过才生成动作和碳主张；
- **非简单并列效果**：系统可显示一个候选因电压、连续供电、GFM 或服务预算而被阻断，而不是仅输出一个总目标值；
- **对照证据**：同一场景、同一资源、同一故障下，比较“无 CareTask”“无物理反馈”“无服务锚点”的误入推荐/失败比例和结果差异。

### 7.3 实施充分公开风险

- 需要把每个输入字段、单位、时间步长、容差、任务依赖表达、资源容量、P/Q 规则、反馈停止条件和失败判定写清；
- 需要至少给出三个灾害实施例、一个不可行实施例、一个服务合同失败实施例和一个证据篡改/不一致实施例；
- 需要明确“模型假设”和“真实场景接入”两类数据来源，不用示例数值冒充现场数据；
- 需要让权利要求不依赖某个私有 Python 包、某个固定 solver 或 33 节点算例；实现例可使用 CVXPY/Python，权利要求应表述为约束求解和物理校验步骤；
- 避免把源码复制到交底书代替技术解释；关键在数据流、控制流程、约束关系、状态转移和技术效果。

### 7.4 自由实施（FTO）风险

本报告未完成 FTO。即使自身申请获授权，商用实施仍可能落入他人关于配电自动化、微网控制、储能 EMS、恢复优化、SCADA/DMS 接口或碳管理软件的权利要求。进入客户 PoV 或产品化前，需对目标国家/地区和拟部署功能单独开展 FTO 检索。
