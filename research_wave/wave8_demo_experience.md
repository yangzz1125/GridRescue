# GridRescue 竞赛演示 UX 评审与改造蓝图（Wave 8）

**范围：** 基于 `app.py`、README、`flood_v08` 证据包及既有答辩材料的只读评审；本报告不改生产代码。  
**目标：** 在 3 分钟内让评委形成一个结论：系统先锁住生命线服务，再用潮流/成岛筛掉假可行方案，最后把碳结论封装成可回放证据；它不是八个分散的技术页签。

## 1. 当前问题与演示原则

现有首屏有六个指标和八个并列 Tab（数字孪生、策略、能源碳流、潮流、MRV、Pareto、成岛、生命线）。功能完整，但评委需要自己拼出“推荐为何可信”的因果链：

`灾害与服务合同 → 候选方案 → 物理门 → 碳—服务权衡 → 证据封签`。

**重构原则：**

1. **一屏一决策。** 首屏只回答“推荐哪个候选、是否有资格被推荐、代价是什么”。
2. **三门固定可见。** 服务门、物理门、证据门与 `E 类合成竞赛输入` 常驻，低碳数字不脱离服务代价出现。
3. **主舞台+证据抽屉。** 把八页内容收敛成一个工作台；深入数据通过右侧抽屉/底部证据轨进入，避免 Tab 跳转。
4. **以反例建信任。** 现场必须展示一次 `BLOCKED: NO_GFM` 或 Pareto 失败点；“被系统拦截”比“更多图表”更能证明创新。
5. **用绝对值、显式约束和单位。** v08 主 run 的碳因子口径为 **kgCO2**，界面、图轴和口播统一用 kgCO2；若 `same_service_reduction_claim_allowed=false`，不可称“同服务减排”。

## 2. 建议信息架构：一个决策工作台 + 三个证据区

### 常驻控制条（顶端，单行）

- 左：项目名 + `预案级 / case33bw / E 类合成输入`。
- 中：灾害场景、恢复时刻、演示预设（`主推荐` / `被拦截反例` / `稳健性`）。
- 右：`运行 ID`、`Verified` 状态、`导出证据包`。
- **默认锁定** “暴雨内涝 + 主 run `run-7e495c4e6e73c188` + 推荐候选”；策略选择不再是第一个决策控件，改为“比较对象”。

### A. 决策工作台（默认且唯一主页面）

1. **结论带（高度约 120px）**：推荐状态、三门 badge、碳—服务 trade-off、关键服务完成度。
2. **行动画布（左 2/3）**：电网拓扑+共享小时游标；以故障、联络线、带电/失电、服务节点四层编码。
3. **推荐理由（右 1/3）**：三条机器可读理由：服务合同、最低电压/最大载流率、碳清单与普通 EENS 增量；附“查看证据”锚点。
4. **决策条（画布下方）**：仅保留 2 个候选的 Pareto 比较（服务锚点 vs 受控预算点），不是四个点的技术表。
5. **操作时间线（右侧可折叠）**：当前时刻的动作、影响节点、理由及完成状态。

### B. 证据抽屉（从工作台右侧打开，非 Tab）

- **服务证据**：CareTask 卡片（ICU/急诊/冷链等）、deadline、功率/电压、完成状态、失败码。
- **物理证据**：24h `Vmin`/`loading` 双图、当前孤岛护照、`BLOCKED/DEGRADED` 原因、支路/节点明细。
- **碳与 MRV 证据**：活动数据→因子→排放分项瀑布图、claim gate、run manifest、11 文件 verify、hash/seal、下载。

### C. 备用页/答辩备份区（演示不主动进入）

- 三策略完整对照、完整 Pareto 扫描表、30 场景压力测试、完整潮流表、原始 CSV/Markdown 下载。
- 这些功能仍在系统中，但从主故事中退出；评委追问时由“证据索引”直达。

## 3. 视觉层级与状态语言

| 级别 | 内容 | 视觉规则 |
|---|---|---|
| L1 决策 | 推荐/不推荐；三门状态；碳—服务代价 | 顶部强对比结论带；一句话且全屏唯一主标题。 |
| L2 影响 | 关键任务完成、普通 EENS 增量、Vmin、最大载流率 | 4 张紧凑指标卡，只保留可改变推荐结论的数。 |
| L3 行动 | 拓扑、时刻、动作、故障与孤岛 | 大画布；颜色和线型严格固定。 |
| L4 可追溯 | 哈希、因子快照、原始表、诊断明细 | 置入抽屉/下载，不和 L1 抢焦点。 |

**颜色语义（全局一致）：** 绿=通过/带电，红=故障或 BLOCKED，琥珀=代价/DEGRADED/受控让步，蓝灰=中性网络或证据。碳的减少不要单独使用“胜利绿”；只有门状态绿时，碳差才可着绿框。每个碳数字紧邻 `普通 EENS Δ` 与 claim status。

**文案规则：** 固定使用“运行碳清单差额”“受控普通服务预算”“物理通过候选”；避免“显著减排”“核证”“实时部署”“最优”。

## 5. 3 分钟点击路径（预录/现场均可复现）

**预设：** 把场景、小时、候选、证据 run 固定到暴雨主 run。避免现场点击“运行 Pareto 扫描”；扫描结果须预热缓存或读冻结工件。

| 时间 | 点击/画面 | 评委看到的证据 | 口播要点 |
|---:|---|---|---|
| 0:00–0:20 | 打开工作台，拓扑处于 T+0→T+6 自动推进 | 故障线、风险服务节点、三门灰→评估中 | 灾后恢复要同时回答服务、物理与碳。 |
| 0:20–0:45 | 停在推荐候选结论带 | 服务/物理/证据三门，碳差与普通 EENS Δ 同屏 | 系统不把“少供电”包装为低碳。当前是受控服务预算下的碳—服务权衡。 |
| 0:45–1:15 | 点击“查看服务” | 4 个 CareTask、2 个一级任务、deadline、最小电压、4/4 | 关键负荷被拆为有时限和最低功率/电压的合同。 |
| 1:15–1:45 | 点击“查看物理”；切换 `被拦截反例` | `BLOCKED: NO_GFM` 或失败 Pareto，随后回到 PASS 候选 | 有电量不等于可保供；不满足成网/电压/热限即不能进入推荐。 |
| 1:45–2:15 | 回到主画布，打开两点 Pareto 决策条 | 服务锚点 vs 6%（或冻结主证据的预算点）；绝对 carbon 与 normal EENS | 只在相同医院/关键合同下允许普通服务显式让步，代价被量化。 |
| 2:15–2:40 | 点击“查看 MRV” | `run-7e495c4e6e73c188`、11 files、`verified=true`、因子/动作/输出链 | 每个结论可回到输入、因子、动作账本与校验结果；seal 是完整性而非第三方实测认证。 |
| 2:40–3:00 | 展开“稳健性/回放”迷你卡；回到结论带 | 30 场景成功/失败、replay 入口；路线图 | 当前是公开算例的预案级骨架，真实馈线与因子替换输入即可复算。 |

**备用操作：** 若网络图加载慢，先展示冻结截图/录屏并跳至 MRV drawer；不得在 3 分钟内等待 Pareto 计算。

## 6. 图表取舍：保留六张，替换四张

| 目的 | 推荐图表 | 设计要求 | 替换/避免 |
|---|---|---|---|
| 灾情与动作 | **交互拓扑图** | 共享小时游标；故障红虚线、已闭合联络线青色、服务节点图标；点击节点打开证据。 | 固定 spring layout 每次应保持坐标稳定，避免视觉跳动。 |
| 推荐理由 | **碳—服务 trade-off 点图** | x=普通 EENS，y=kgCO2；只展示锚点、推荐点、一个被拦截点；显示合同/物理状态。 | 目前 4 点完整折线与大表作为备份。 |
| 物理可信度 | **双轨阈值趋势** | 上轨 Vmin（阈值线），下轨 max loading（100%线）；同一小时 marker 联动拓扑。 | 不把 pu 与百分比叠在同一 y 轴。 |
| 任务可信度 | **CareTask 时间甘特/服务热图** | 行=任务，列=小时，颜色=满足/未满足；deadline 竖线。 | 单纯任务完成率卡片不足以解释。 |
| 碳可追溯 | **排放瀑布图/100%分项条** | grid、diesel、crew 三项；清楚区分直接清单与弃电机会损失。 | 现有能源 area 中把 `pv_available_kw` 当供给层会造成误读；应分“可用/消纳/弃电”。 |
| 可靠性 | **成功—失败小倍图** | 30 场景的成功/失败、P50/P90 EENS、replay ID。 | 只报一个“29/30”数字。 |

现有“三策略相对值柱图”建议退出主屏：其归一化相对值让量纲、方向和绝对代价不直观。若保留在备份，改为小倍图绝对值+差异注释，并固定比较基线。

## 7. 证据显示规范

### 决策证据卡（首屏永远可见）

- **服务门：** CareTask `4/4`、Tier-1 `2/2`、普通服务预算 `x%`、合同定义 SHA 前 12 位。
- **物理门：** `24/24h` 可行、Vmin、max loading、岛状态；出现失败时只显示失败码而不是静默过滤。
- **证据门：** run ID、`verified=true`、checked files=11、seal hash 前 12 位、数据等级 `E_synthetic_demo`。
- **声明门（和碳并排）：** `same_service_pass` 与 `same_service_reduction_claim_allowed`。v08 中二者为 false，因此文案为“controlled service budget inventory difference”。

### 抽屉中的证据递进

1. **一眼可审：** PASS/BLOCKED、数值、单位、约束、数据等级。
2. **一点击可解释：** 任务失败码、岛最弱约束、P/Q/热限/电压曲线、排放分项。
3. **一下载可复核：** claim_gates.json、verification.json、seal.json、factor snapshot、actions/activity/emission ledger、CSV。

## 8. 优先级路线图

### P0 — 演示前必须完成（可信度）

- [ ] **冻结主 run 与数字字典。** 设定唯一 `GR-COMP-01` factsheet，绑定 UI/PPT/视频/导出文件；禁止 UI 默认计算的新数字混入。
- [ ] **将首屏收敛为工作台。** 首屏显示三门、数据等级、推荐结论、碳—服务 trade-off、拓扑；八 Tab 从默认路径移除。
- [ ] **修正碳和声明口径。** kgCO2 替换 kgCO2；碳差旁显示普通 EENS Δ 与 same-service gate；主口播禁止“同服务减排”。
- [ ] **加入一个被拦截反例预设。** 20–25 秒内可打开 `BLOCKED: NO_GFM` 或 Pareto failure，再回到合格候选。
- [ ] **MRV 顶层化。** 主屏能看见 `run-7e495c4e6e73c188`、`verified=true`、11 文件、E 类合成边界；seal 含义明确为文件完整性。
- [ ] **演示稳定性。** 预加载主 run 和 Pareto，窗口 1366×768/1920×1080 两档验收；准备离线录屏备份。

### P1 — 提升得分差异（产品感）

- [ ] CareTask 甘特/服务热图，点击任务可高亮拓扑节点和对应时间。
- [ ] Vmin/loading 双轨图与小时游标联动；支路/节点点击显示当前值与阈值。
- [ ] 将能源 area 拆为“供能调度”和“碳清单”；增加 grid/diesel/crew 瀑布图。
- [ ] 完整策略比较改为绝对量小倍图，加入“为什么此策略不被推荐”解释。
- [ ] 将 `MRV报告` 变成 evidence index：文件树、预览、hash、下载、verify 语义。
- [ ] 30 场景小卡：成功/失败、尾部 EENS、replay 入口，作为收束或追问页。

### P2 — 有余力再做（不挤占证据闭环）

- [ ] 可分享的“决策快照”URL/PNG：冻结 scenario/hour/candidate/run ID。
- [ ] 键盘演示快捷键与 presenter mode（`1=主推荐, 2=反例, 3=MRV`）。
- [ ] 真实馈线/因子/任务字典的数据接入映射页。
- [ ] 更细的地图、3D、AI 叙事；只在有真实数据和验证时进入主展示。

## 9. 验收检查

### 30 秒评委理解度

- [ ] 首屏无需切页即可回答：推荐/不推荐是什么、三门是否通过、碳差的服务代价是什么、数据是否为合成。
- [ ] 不读说明文本，评委也能从视觉区分通过、受控让步、故障/拦截。
- [ ] 首屏关键数不超过 6 个；每个数均有单位与语境。

### 3 分钟可演示性

- [ ] 演示员从刷新页面到三门、CareTask、拦截反例、Pareto 两点、MRV PASS、稳健性卡的点击路径 ≤ 8 次、≤ 180 秒。
- [ ] 不依赖现场运行耗时超过 1 秒的扫描；冻结结果已加载。
- [ ] 画布、抽屉和数据表在 1366×768 上无横向截断；每一动作有失败/加载态。

### 科学与声明纪律

- [ ] 所有碳单位与 v08 factor snapshot 一致为 kgCO2，或有正式 CO2e 映射证据。
- [ ] `same_service_reduction_claim_allowed=false` 时，碳差旁必有普通服务预算/normal EENS Δ，且无“同服务减排”文案。
- [ ] `BLOCKED`/Pareto failure 具有可见失败码和筛除理由；失败点不被绘制为推荐候选。
- [ ] CareTask 明示 E 类合成模板；护照明示 GFM/黑启动为模型推断，非现场 VERIFIED。

### 可复核性与匿名

- [ ] 从首屏可下载或定位 claim gates、verification、seal、factor snapshot、actions 与排放账本。
- [ ] verification 显示 `verified=true`、`checked_files=11`，并解释仅为完整性/可复算校验。
- [ ] 录屏、截图、下载文件、浏览器标题和默认路径均无学校、人员、用户名或绝对本机路径。

## 10. 最终演示句

> GridRescue 的价值不在于展示一个更绿的数，而在于先把生命线合同、物理可行和可验证证据设为三道门；没有通过这三道门，任何低碳数字都没有资格进入推荐。
