# GridRescue Wave 10：竞品差异化地图与答辩定位

**正式日期：2026-08-22**  
**用途：** GridRescue（碳韧智网）双碳/韧性类学术竞赛申报、答辩与演示脚本；不修改生产代码。  
**定位边界：** 本报告比较的是常见参赛作品和产品能力类型，不把它们等同于某一家厂商的完整产品能力。GridRescue 当前是基于 IEEE/MATPOWER `case33bw`、E 类合成工程输入的预案级原型；现有 V08 三个正式 MRV bundle 的 `same_service_pass=false`，故只能陈述为“生命线不降级、普通服务受控预算下的运行碳清单差异”，不得陈述为已获得“严格同服务减排”结论。

---

## 0. 一句话结论

> **先守住生命线，再守住电网，最后守住每一公斤碳的证据。**

这句话的关键不在“低碳”三个字，而在顺序：**服务合同 → 物理可行 → MRV 证据**。任何一门未过，系统不把更低的碳数字包装成推荐。

---

## 1. 比较口径：GridRescue 不和成熟工业系统比“功能菜单”，而比“推荐资格”

常见作品或产品在一个单点上往往很强：碳看板擅长清单，能源管理擅长日常优化，预测擅长提前量，微网调度擅长资源协调，FLISR/灾后恢复擅长复电，数字孪生擅长态势可视化。GridRescue 的竞争位置不是宣称替代 ADMS、SCADA、OMS、EMS 或第三方核证，而是把它们之间通常断开的四个问题压进同一条审计链：

1. **服务是否真的守住？** 以 `CareTask` 的最低功率、时窗、deadline、连续时长、依赖与任务电压门为合同，而非一个“关键负荷权重”。
2. **方案是否真的可执行？** 候选必须经故障隔离、径向性、成岛平衡、P/Q 潮流、电压、热限和无 GFM/无电源孤岛拦截。
3. **碳差是否有比较资格？** 先判定服务锚点与 epsilon 预算；服务不等价时只显示公开服务代价和清单差异。
4. **数字能否被复核？** 用动作—活动数据—因子—逐时清单—manifest—hash—verifier 连到可下载证据包。

换句话说：**GridRescue 的赛道不是“多做一个模型”，而是“让恢复建议有资格被展示、被比较、被复算”。**

### 1.1 公开信息对照：为什么这些类别会成为常见竞品

- FLISR/配网自动化的核心通常是故障定位、隔离、转供和缩短停电影响；行业方案亦将其描述为通过开关动作恢复健康馈线的供电。GridRescue 承接其恢复动作，但进一步要求动作同时过服务、物理和碳证据门。[SEL, FLISR](https://selinc.com/solutions/p/flisr/)
- 电力系统数字化与数字孪生通常强调数据、分析、可靠性、效率和运行态势；这解释了“拓扑可视化 + 大屏”会成为高频作品形态。GridRescue 的差异是把孪生输出绑定到可失败的推荐门与证据包，而不是停在画面层。[IEA, Digitalisation and Energy](https://www.iea.org/reports/digitalisation-and-energy)
- 温室气体清单框架强调活动数据、排放因子、透明披露和电力相关核算口径；GridRescue 将这一思路下沉到灾时“每个动作、每一小时、每次比较”的可追溯记录，但当前仍是方案级、内部复算层，不替代现场测量或第三方核证。[GHG Protocol, Scope 2 Guidance](https://ghgprotocol.org/scope-2-guidance)

## 2. 七类常见竞品的“能力—缺口—GridRescue 反位”地图

| 常见类别 | 通常主问题 | 常见交付物/评委印象 | 易出现的比较空白 | GridRescue 的反位与答辩说法 |
|---|---|---|---|---|
| **碳看板/碳驾驶舱** | “排了多少、哪里排得多？” | KPI、趋势图、碳源拆分、排行榜 | 碳数常在决策之后出现，难追到灾时开关/调度动作；服务差异被隐藏 | “我们不只看排放结果；每个候选的动作、活动账、因子、清单和 hash 都能反查。” |
| **能源管理/综合能源优化** | “日常怎样降低能耗或成本？” | 负荷曲线、储能削峰、设备策略 | 多按正常运行设计；灾害多故障、孤岛、关键任务时限与恢复顺序较弱 | “我们把日常能管的资源调度放进灾时恢复，不允许用常态最优替代灾时可执行。” |
| **负荷/新能源预测** | “未来负荷、光伏或风险是多少？” | 预测模型、MAE/RMSE、预警 | 预测值未必进入一个有服务合同和电气校验的恢复决策 | “预测只是输入；我们交付的是受扰动后仍需通过三门的候选与失败原因。” |
| **微网/储能调度** | “DER 怎样供电、削峰、孤岛？” | SOC、功率分配、成本或弃电 | 容易把“有储能”推演成“可成岛”，或把放电误读为零碳 | “无 GFM、黑启动或资源边界的孤岛会被 BLOCKED；电池不因放电就获得低碳标签。” |
| **低碳调度/Pareto 优化** | “EENS、成本、碳怎么折中？” | 加权目标、Pareto 曲线、最优点 | 可能以少供电换低碳；每一个 Pareto 点的物理/服务资格不透明 | “我们先锁医院、关键和普通服务锚点；每个前沿点都重做服务、潮流与 MRV gate。” |
| **通用数字孪生** | “系统现在什么状态、能否仿真？” | 三维/拓扑、热力图、动画、告警 | 可视化很强但结论往往缺少反事实、可复算和主张边界 | “我们的孪生不仅‘看见’，还记录‘为什么推荐、为何拦截、如何复核’。” |
| **灾后恢复/FLISR/OMS 方案** | “怎样更快隔离故障、恢复更多负荷？” | 故障定位、重构、恢复率、EENS | 常以复电速度/失供为主，碳与关键服务常被并列 KPI 而非硬门 | “我们保留恢复的主链，但把生命线任务、物理反馈和碳清单变成推荐准入条件。” |
| **碳核算/MRV 工具** | “清单能否核对、因子是否可追溯？” | 因子库、台账、报告、审计轨迹 | 通常不理解电网拓扑、故障动作、服务合同和潮流可行性 | “MRV 不是报告尾页，而是恢复候选的资格审查器；文件能验，动作也能追。” |

### 2.1 对比时必须承认的边界

- GridRescue **不是**工业实时 ADMS/SCADA/OMS，也不对现场开关下控；其当前最合适的位置是“灾前预案、演练、复盘与方案级决策支持层”。
- GridRescue **不是**现场碳核证系统；`SEALED` 与 `Verification=PASS` 表示证据文件完整性、内部引用和方程复算通过，不等同第三方核证。
- `Carbon-SOC` 是已有研究设计和后续升级方向，当前代码的既有能力是动作级 MRV，不应把未落地的储能碳来源账本作为现有卖点。
- 当前高价值结论是“**受控服务预算下的可审计权衡**”；严格同服务结论应等待 C0 严格配对实验与 gate 证据齐备后再使用。

## 3. 可直接用于申报书、PPT 和答辩的 28 条差异化陈述

> 使用规则：每条只在对应证据存在时使用；数字类表述须同屏给比较对象、单位、服务边界与证据路径。

### A. 问题定义差异（1–7）

1. **不是“灾后多快复电”，而是“哪些生命线任务在何时、以何种物理证据被恢复”。**
2. **不是“碳排低不低”，而是“这个碳差在相同或公开差异的服务合同下是否有比较资格”。**
3. **不是将医院列为高权重负荷，而是将 ICU、手术、冷链、通信等拆成可失败、可验收的 `CareTask`。**
4. **不是把电网恢复、电源调度和碳核算并列展示，而是把三者作为同一候选的因果链。**
5. **不是用一个加权总分掩盖取舍，而是保留医院—关键—普通服务锚点与公开 epsilon 预算。**
6. **不是只奖励“更低碳”的策略，而是先识别“少供电导致账面更低”的伪优势。**
7. **不是追求一个总冠军算法，而是输出一组带资格标签的可解释恢复方案。**

### B. 决策与物理差异（8–14）

8. **每个推荐候选都要穿过故障隔离、径向性、成岛平衡、P/Q 潮流、电压和热限，而不是仅在目标函数中获胜。**
9. **无电源、无 GFM 或资源越限的孤岛被明确 BLOCKED；系统不靠虚拟 slack 把功率缺口伪装成已供电。**
10. **恢复动作不是抽象的“优化结果”，而是可回放的联络、修复、柴油、储能和购电动作序列。**
11. **对每个 Pareto 点重新进行物理反馈，失败点留在失败表而不是从图上静默消失。**
12. **传统顺序、最小失供与碳韧协同使用同一灾情、资源和需求输入，强调反事实而不是单方案自证。**
13. **从“优先级”升级为“服务合同”：最低功率、deadline、连续服务、依赖关系和任务电压阈值共同决定是否履约。**
14. **从“有储能即可保供”升级为“储能/柴油/PV/上级电网在节点、岛屿和潮流边界内共同可行”。**

### C. 碳与 MRV 差异（15–22）

15. **碳边界落到柴油、购电、抢修交通和网络损耗等活动数据，不把恢复电量直接等同于减排。**
16. **新能源弃电作为机会损失单列，不把它混入主排放清单制造漂亮数字。**
17. **碳因素从“结果看板”进入候选筛选逻辑：服务不等价时，系统撤回严格同服务主张。**
18. **每一小时的活动账、因子快照和 kgCO2 清单可被独立 verifier 重算，而不依赖演示者口头解释。**
19. **因子注册表、输入快照、动作终端 hash、evidence index 和 seal 形成可下载的证据包，不只截一张 dashboard 图。**
20. **“Verification PASS”被严格限定为文件完整性与内部方程复算，主动区分于现场测量和第三方认证。**
21. **主张门（claim gate）决定文案：`same_service_pass=false` 时只能显示受控服务预算下的清单差异。**
22. **碳数字始终与普通 EENS 增量、epsilon、关键任务完成与物理状态并排，防止绿色数字脱离服务语境。**

### D. 竞赛呈现与可落地差异（23–28）

23. **不把数字孪生做成八个平权 Tab 的大屏拼图，而收敛为“推荐—三门—证据抽屉—追问库”的决策工作台。**
24. **演示不仅展示主推荐，也展示被拦截反例；评委能看到系统为何拒绝一个看似低碳却不合格的方案。**
25. **用冻结 run、run ID、hash、版本化因子和下载包组织材料，使 PPT、视频、UI 与导出报告保持同一事实源。**
26. **把不确定性与失败场景保留为结果的一部分：失败隔离、replay manifest、置信区间和未通过 gate 都可追。**
27. **以“预案级、轻量接入层”衔接既有 ADMS/OMS/医院后勤/综合能源服务，不虚构取代控制系统的承诺。**
28. **评审价值不靠堆 AI、3D、区块链或概念词，而靠一个可被 30 秒理解、3 分钟复核、尖锐追问可回查的决策闭环。**

## 4. 2×2 定位图：把 GridRescue 放在“决策资格”而非“炫技看板”象限

### 4.1 坐标定义

- **横轴：从“事后可视/统计”到“灾时行动级决策”**  
  左侧偏看板、报表、预测；右侧偏动作、重构、资源配置与恢复顺序。
- **纵轴：从“单一指标/模型输出”到“服务—物理—证据三门闭环”**  
  下侧可解释但资格弱；上侧要求服务合同、物理可行和 MRV 复核共同成立。

```text
                        高：服务—物理—证据闭环
                                   ↑
                                   │
   碳核算/MRV工具                    │        GridRescue（目标位）
   ─ 因子、清单、报告                │        ┌─ CareTask 服务合同
   ─ 多在决策之后                    │        ├─ 潮流/成岛/热限 gate
                                   │        ├─ 动作级 MRV + verifier
                                   │        └─ 主张语义锁与反事实比较
                                   │
   通用数字孪生/碳驾驶舱              │        灾后恢复/FLISR + 低碳调度
   ─ 态势、可视化、KPI                │        ─ 重构/转供/资源调度强
   ─ 缺少候选资格链                  │        ─ 常缺服务合同或碳证据门
                                   │
───────────────────────────────────┼────────────────────────────────→
        左：事后可视/统计            │           右：灾时行动级决策
                                   │
   通用能源管理/负荷预测              │        微网/储能优化、最小失供调度
   ─ 常态能效、成本或精度             │        ─ 资源协调、EENS/成本/Pareto
   ─ 未必涵盖灾时多故障               │        ─ 易停在单一目标或可行性假设
                                   │
                                   ↓
                        低：单一指标/模型输出
```

### 4.2 图的讲解话术（20 秒）

> “左下角的工具解决日常监测或预测，右下角的工具已经会调度和恢复；但评委真正会追问的是：低碳是否靠少供电、孤岛是否真能供、数字是否能复算。GridRescue 放在右上角：每个恢复动作先过生命线服务、再过电网物理、最后过碳证据，才获得推荐资格。”

### 4.3 防守性说明

右上角不是“所有能力都比工业系统强”，而是**在竞赛原型所覆盖的灾时方案级决策链中，三类资格同时显式化**。成熟工业 ADMS/FLISR 的实时性、设备通信、保护配合和控制安全仍是其优势；GridRescue 的合理角色是接入其数据/动作接口，为预案比较、演练与审计补足“服务—物理—碳证据”的一层。

## 6. 最推荐的申报书定位段（可直接引用）

GridRescue 面向极端天气下配电网多点故障恢复中的一个被忽略问题：**一个“更低碳”的恢复建议，凭什么有资格被展示给决策者？** 平台不把碳排作为恢复后的附加看板，而是将医院等生命线任务的服务合同、配电网的 P/Q 潮流与成岛可行性、以及动作级 MRV 证据共同设为推荐门槛。系统在同一灾情、资源与需求输入下并排回放传统恢复、最小失供和碳韧协同方案；只有通过服务、物理和证据三门的候选，才进入可解释的碳—服务权衡比较。由此，项目将“更快复电”“更低碳”和“更可信”从三个并列 KPI，转化为一条可追溯、可复算、可履约的灾时决策链。

## 7. 展示执行建议：一张图、一句 claim、三个证据动作

### 7.1 首屏必须出现的四个元素

1. **一句 claim：** “先守住生命线，再守住电网，最后守住每一公斤碳的证据。”
2. **三门资格卡：** 服务门 / 物理门 / 证据门，显示 PASS、BLOCKED 或待复核及来源。
3. **碳—服务绑定卡：** kgCO2 差、比较对象、普通 EENS Δ、epsilon、claim status 同屏。
4. **反例入口：** “为何未推荐？”一键展示 `NO_GFM`、潮流失败、服务失败或证据失败的具体原因。

### 7.2 30 秒口播

> “灾害来临时，最快复电未必最低碳；更低碳也可能只是少供了普通负荷。GridRescue 不先展示绿色数字。它先用 CareTask 守住生命线，再用潮流和成岛约束守住电网，最后用动作级 MRV 守住每一公斤碳的证据。三门都通过，候选才有资格被推荐。”

### 7.3 三个评委追问的短回答

- **“这和低碳调度有什么不同？”**  
  “我们不把 EENS、成本、碳排塞进一个分数；先锁服务合同，再对每个候选重做物理与 MRV gate，服务不等价就撤回严格同服务碳主张。”
- **“这和数字孪生有什么不同？”**  
  “不是展示一个会动的电网图，而是把推荐理由、拦截理由、动作链、因子、清单和 hash 放在同一可复核闭环里。”
- **“这和灾后恢复/FLISR 有什么不同？”**  
  “恢复动作仍是主链，但我们把生命线时限、成岛可行和碳证据纳入推荐资格；更快恢复与更低清单都不能绕过这三门。”
